# 模型评测复核前的约定

上轮已经知道，GoEmotions 发布测试集有 468 个评论在两种标签定义间发生变化。本轮固定模型、预测方式和评价后，才计算模型得分和排序。目前已核对模型卡、版本与运行环境；尚未运行本轮测试预测，也未查看任何与两列标签配对的模型结果。这是已知标签差异上的新分析。

- 数据固定为上次的 5,427 个官方测试 ID，以公开细标签映射得到的粗标签为 G₀，以先在每位标注者内部映射、再取两人支持得到的为 G₁。采用上次公开的词表与映射，含 neutral。G₀ 是 G₁ 的子集。
- 使用 SamLowe 的同一 RoBERTa 分类器的两个公开 ONNX 部署版本，固定提交 `90ee0c1c4796d370e68968687b8ba51fc11224f4`，一份全精度，一份作者发布的 INT8。主比较为两者各自对细类用固定 sigmoid 概率 ≥0.5（logit ≥0），再按官方映射合成粗类。允许空预测。次要、预先规定的行为对照是同一全精度模型每例只选 logit 最高的一项，再映射为粗类；并列时选最小细类索引。只报告“全精度阈值与 INT8 阈值”“全精度阈值与全精度单选”两对。
- 使用上游 tokenizer、测试 TSV 原文与原有行顺序，CPU、单例独立推理、无补齐、截断上限 128 个 token，统计截断数。锁定 Python 3.13、ONNX Runtime 1.23.2、tokenizers 0.22.1 和 NumPy 2.3.3。预测程序只读取文本和键，以独立文件锁定三套预测，评分程序随后按键连接两种标签。记录平台、执行提供程序和线程设置。作者已在原测试集展示过模型表现，因此这些测试记录不是模型开发历史上的盲测集。阈值未经本轮调优。
- 主指标为跨七个标签的 micro-F1，次指标为整条评论标签集合完全匹配率。报告两个端点的全部分子分母、逐标签新增命中数量和两次排序，包括相同结论及平局。对固定预测，参照集合中新增的标签可能原先已被预测，也可能漏掉；用精确整数对账这两种情况。
- 额外检验一个明确的敏感性问题。若逐条复核时，468 条有差异的评论允许各自采用两种定义之一，每次整体切换一条评论，不得拆开该条的新增标签。求两套固定预测的 micro-F1 差值可达的最小和最大值、从 G₀ 出发让原排序严格翻转的最少切换评论数（若有），并回放见证。这个假设与必须全库使用同一解释的情形分开报告，也不代表任一混合标签集是人的真实情绪。用小规模全枚举对照，实测若排序稳定也照实发布。
- 原有工作已研究标注分歧、模型评价和标签噪声对排名的影响。本轮查验的是上述固定数据、真实公开部署和可复核的整条评论敏感性。两种精度共享训练所得权重，不能作独立学习架构比较。此前的两份语言任务研究亦未证明一般推理能力提升。[模型发布者](https://huggingface.co/SamLowe/roberta-base-go_emotions-onnx) · [GoEmotions 收集者](https://aclanthology.org/2020.acl-main.372/) · [此前的逐条对账](goemotions.md)
