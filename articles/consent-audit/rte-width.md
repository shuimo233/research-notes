# 让每道题独立推理，把补齐宽度选得更像普通组批，答案会更好吗？

同一份量化蕴含模型，把题目单独计算或按八条成批计算，可能给出不同答案。在此前看过的 277 道题上，普通组批多答对了 9 道。我们据此登记一个猜想：只用别的题有多长，给每道题选一个固定的补齐宽度，也许能保留部分收益，同时让它的答案独立于当前同批的题。旧数据看起来支持这个猜想。在首次计分的 1,823 道题上，宽度误差降了 57.5%，判决分歧从 73 增至 77 道，正确数从 1,302 降至 1,288。按评分前公布的两项条件，这条规则失败了。[事前登记](https://github.com/shuimo233/research-notes/blob/6842272b2979c69a8185a447cbb7a8b47c754050/articles/consent-audit/rte-width-protocol.md) · [逐题原始分数](rte-width-logits.tsv)

## 要求判断“有理由”，应当怎样检验

任务要求模型判断，单凭给出的前提能否推出假设。同批另一道题没有为这道题提供理由，因此我们可以要求，换掉一起送入模型的题目时，这一道的判断保持一致。还有一个独立的选择：一道题单独算时，应该补齐到多长？两个实现都可以满足逐题独立，却得出不同的答案。上一轮实验精确复现了最短单例，这一轮检验另一种同样固定的参考行为。[最短单例对照](pointwise.md)

在官方 RTE 训练文件中按题目 ID 的固定哈希选出 667 道作校准，只使用其分词长度。对每道待评题，设想从校准池等概率无放回抽取七道陪同组批。记 $N$ 为池中题数，$F(a)$ 为长度不超过 $a$ 的题数，七道中最大长度不超过 $a$ 的概率为 $\binom{F(a)}{7}/\binom{N}{7}$。这个最大长度的较小中位数是 **138 个词元**。对本题长度 $\ell$，固定宽度取 $\max(\ell,138)$。它是包含本题后的随机批宽的一个中位数，因此使该抽样模型下的期望绝对宽差最小。现实队列保持原文件顺序。宽差与判决分别计分。[有限总体顺序统计量](https://arxiv.org/abs/2207.00270) · [绝对损失下的中位数预测](https://arxiv.org/abs/0912.0902) · [实际校准分布](rte-width-calibration.json)

## 两批题给出了不同的答案

每项用同一冻结模型和二元蕴含规则评分。“分歧”是与原文件顺序普通八条组批的二元判断不同的题数。“宽差”是每题补齐宽度与所在普通批宽度的绝对差之和，单位是词元。

| 执行方式 | 新评估题正确数 / 1,823 | 分歧 | 宽差 | 旧开发题正确数 / 277 | 分歧 | 宽差 |
|---|---:|---:|---:|---:|---:|---:|
| 最短单例 | 1,302 | 73 | 129,176 | 194 | 9 | 20,037 |
| 单例向上补齐到 32 的倍数 | 1,298 | 79 | 109,962 | 194 | 9 | 16,805 |
| 单例至少补齐到 138 | 1,288 | 77 | 54,924 | 199 | 6 | 8,251 |
| 普通八条组批 | 1,289 | 0 | 0 | 203 | 0 | 0 |

在新评估题上，138 规则相对最短单例纠正了 23 道，也失去了原来答对的 37 道。它比补齐到 32 倍数的对照少了 2 道分歧，少答对 10 道。普通组批自身也有两种方向的变化，纠正 30 道，失去 43 道。仅比较汇总正确数会漏掉这些逐题差异。[逐项统计](rte-width-scores.json)

在旧开发题上，138 规则达到事先定下的 199 道门槛。它挽回了普通组批原先纠正的九道中的四道，另纠正一道两种旧方式都答错的题，没有失去原来已答对的题。净增五道与复现旧九道中的四道，是两个不同的问题。新评估的主要门槛要求相对最短单例同时减少判决分歧、维持正确数；实际两个方向都相反。[逐题复算器](rte_width_score.py)

新增评估的第 1508 题给出了一个可以直接阅读的例子。前提只说鲍里斯·贝克尔曾是德国职业网球运动员，假设说他是温布尔登冠军。即便读者知道他的比赛成绩，单靠给定前提仍推不出这个头衔。最短单例用了 21 个词元，普通批宽是 192，两者都答“不能推出”。把单例补到 138 后，输入宽度接近了 117 个词元，模型反而答“能推出”。这是事后为解释结果选的例子。在全部新增题中，1,282 道的宽度更接近了，其中 25 道引入了新的组批判决分歧，23 道消除了原有分歧。另有 121 道达到了与普通批完全相同的宽度，其中两道仍然判得不同。[全部候选题号与计数](rte-width-scores.json) · [上游 RTE 数据](https://huggingface.co/datasets/nyu-mll/glue/tree/bcdcba79d07bc864c1c254ccfcedcce55bcc9a8c/rte)

## 能用这项结果做什么

如果服务承诺每道题只根据该题的前提与假设作答，就可以选定一种单例行为，再对批量服务逐题校验。我们给原模型导出器增加了最小参考宽度。在一个 ONNX 文件里，每题按自身掩码裁剪，再按配置右补齐；每次收到不同长度的批也可以运行。分别按原顺序和 ID 哈希重组 2,100 道评估题，两次输出都与指定的 138 规则单例逐位相同，每个顺序核对 6,300 个 float32 分数。部署者因此可以同时问两个有直接答案的问题：服务是否执行约定的判断，执行该判断之后能答对多少题。[导出器](go_scan_export.py) · [输入接口](point_runtime.py)

这些数字描述一份冻结的 DistilBERT MNLI 动态 INT8 模型、一个 CPU 运行配置及给定的题序。主要评估题来自上游训练文件，是本项目首次计分的保留题；对模型预训练语料的接触情况未知。校准、新评估、原开发集之间完全相同的句对交集均为零。原始组批的两个末批分别为 7 道与 5 道，按实际批宽计分。形状分桶、绝对损失下取中位数、同批内容改变分类结果均有公开先例。本次可引用的新增证据是具体对照中代理指标和两个判断指标发生背离，并能从逐题记录复核。学术索引与工程档案的有限检索仍可能遗漏相同实验。[检索及先例](go-context-prior.md) · [此前文本分类器组批实验](https://arxiv.org/abs/2610.09111)

## 复算

在本目录执行第一条命令，用固定版本的依赖下载输入、生成模型、重算分数，并与发布文件核对。数据目录可复用，输出目录使用新名字；可用 `--host` 指定 Hugging Face 镜像。独立检查从另一份有校验和的 Parquet 发布文件重建题目、标签和分组，用分词器的批量接口重算六种执行方式的全部 37,800 个分数，同时检验 512 个可能题长各自的绝对宽差最优解。两份发布文件都保留相同的上游来源，独立核对发生在本项目内。只想重新计分时，第二条命令用 Python 3.13 标准库即可运行。[复现入口](rte_width_reproduce.py) · [独立复核实现](rte_width_check.py) · [复核记录](rte-width-checks.json)

```sh
uv run --no-project --python 3.13 --with onnx==1.19.1 --with numpy==2.3.3 --with tokenizers==0.22.1 --with onnxruntime==1.23.2 --with duckdb==1.4.3 -- python -I -B rte_width_reproduce.py rte-data width-replay
python -I -B rte_width_score.py rte-width-logits.tsv rte-width-calibration.json rte-point-logits.tsv
```
