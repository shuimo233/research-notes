
# 冻结协议：同一推理模型共用运行配置时，联合拒绝会怎样变化？

在 MoNLI 的否定测试与正极性文件上使用上游已发布的成对蕴含事实。沿用原有去重方法，共 100 个否定对和 736 个正极性对。每对正反两个方向恰有一个蕴含，两个实况的真答复相异。暂以参考标注作为实验环境的合法答案检查器。该检查器不属于模型本身的能力。

## 采集与运行机制

- 模型、分词器、两份语料及单例零补齐分数基线沿用 monli-direction.py 的固定版本。每道题单独运行 CPU ONNX。比较 0、16、24、32、48、64、96、128 八档最小右补齐宽度。0 表示恰好原长度，八档等概率，有效宽度达到同一长度时允许复用同一次前向计算。发布逐项 float32 位模式，并以既有单例档案核对 0 档。
- 二元分差为蕴含分数减中立、矛盾较大值。正号表示模型答蕴含，负号表示答非蕴含。恰好平分一律拒绝。绝对分差至少达到预设门槛且符合参考答案时，模型分支才放行。全部记录六档门槛 0、1/4、1/2、1、2、4。
- 独立的选择中，1/20 强制拒绝，1/20 经检查器复核后给出真答复，9/10 采用上面的模型规则。这使各档配置下的服务率处于开区间。两个辅助分支的概率都属于实验设计，且每项独立执行。
- 一个四项目录只在选择运行配置时共享随机量。以概率 L 共享一档，其余概率各项独立挑档，两路使用相同均匀分布。L 的操作区间为 [0, 1/2]。独立路使联合概率有明确的乘积下限，而且改变 L 不改变任何单项率。

## 目录、对照与验收

对每个语料，按每对按字典序排列后的两个句哈希，以 SHA-256 对 "runtime/v1/" 加两哈希连接串排序。摘要末字节为奇数时交换两方向归到实况一、二的顺序。顺序每四对编成一个目录，所有目录都评分。主要目录不依赖模型分数。

附设诊断目录，每个门槛分别只用此前已发布的单例和普通八题组批分数重排目录，运行本轮的新宽度前固定规则。先按两实况发生放行改变的总数降序排，再按四个放行位的元组排序，最后按相同摘要打破平手。重新每四对成一组。全部目录评分，结果与主目录分别报告。

对每项、二项、三项、四项查看两个实况全拒绝相对各自独立基线的倍数。正反方向两倍数之比均须不超过 21/20。用精确有理数分别算仅二项、仅完整目录、所有至少二项窗口下许可的最大 L。主要指标是仅二项许可的 L 放到完整目录仍超标的目录配置数，及许可的最大 L 损失。记录在 L=1/2 时的完整归一赔率和原始赔率。记录为达到同一风险标准从共享换独立预计增加的最低配置选择数，口径是每批所需的不同配置种数，不是运行耗时。

对模型有效性的前置校验是所有已发表短单例分数逐位一致，并记录各深度、门槛和两语料的零结果。若主要目录没有出现失配，则保留该零结果，不把诊断目录当作首要对照的成功。独立检查器从真实分数重建两条路线的完整概率表、单项率和绑定约束，并验证所给上限可实现，任何增长均会越过至少一项所报约束。
