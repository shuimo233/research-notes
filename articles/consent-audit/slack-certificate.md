# 如何只披露足以复核新版报告的时间戳？

上一轮研究的是在看见精确读数之前，如何算出最小固定名单。这一轮由保管方持有完整记录，审阅方只拿到被披露的时刻、旧档案和新版标签。要求是任何符合旧档案和披露值的时间表都产生同样的报告。于是保管方可以按实况准备更短的证书，审阅方仍可独立核验。

**在有界整数差分约束下，一条新版上界最多有 (n) 个包含极小的反例变更集合，(n) 为可披露位置数。** 所有这些集合只需一次最短路闭包就能列出，与时间刻度跨度无关。每个集合都能配一份时间表，恰好改变集合内的值，并让结论越界一个刻度。最小证书必须从每个集合里至少选一项。公开 CI 回放中，这一构造为全部 430 份报告提供了可独立检验的最少披露数。[上一轮的固定名单](conclusion-replay.md) · [详细证明与查新](slack-certificate-prior.md)

## 从旧报告构造反例

设旧档案蕴含 `x[v]−x[u] ≤ D[u,v]`，其中 `D` 由最短路闭包得到。把真实时间表 `x` 的差值从上界中减去，所得非负余量写作 `E[u,v]`。任一替代时间表 `x+z` 与旧档案相容，当且仅当 `z[v]−z[u] ≤ E[u,v]`，且原点不改变。

要推翻真实成立的上界 `x[v]−x[u] ≤ b`，至少要让差值增加 `h = b+1−(x[v]−x[u])`。旧档案若已给出 `E[u,v] < h`，无需披露。否则可把这次变化拆成从 `u` 减去 `r` 和给 `v` 增加 `h−r`，其中 `0 ≤ r ≤ h`。对每个位置 `i`，这个选择限制其可取的改动：

```text
h − r − E[i,v] ≤ z[i] ≤ E[u,i] − r
```

把零逐点夹在这两个边界之间，得到一份可行反例。两个边界本身都是可行的差分势，逐点取最小或最大保持可行。零落在边界之外的位置，就是必须改变的位置。原点必须能保持为零，所以只考虑它的上下界包含零的 `r`。任一其他可行反例的变更集合都包含某个这样生成的集合。由此得到全部包含极小的反例支持。

对一个位置，允许零改动的 `r` 形成一个区间。可同时不变的最大位置集合对应这些区间的最大重叠集合，每个集合可用其中一个右端点代表。这给出线性的反例集合数上界，并有差分约束实例达到它。程序扫描端点，跳过中间无变化的刻度。标签有上下两条边界时分别核验，全部标签联合变成标准集合覆盖。反过来，用二值时间点表达集合成员约束可把普通集合覆盖嵌入这个问题。已有的精确求解器和加权贪心保证可以直接复用。[构造及紧例](slack-certificate-prior.md) · [覆盖贪心近似界](https://doi.org/10.1287/moor.4.3.233)

一份很短的最低披露证明由互不重叠的变更集合组成。若有 (k) 份反例，且它们改动的坐标两两不交，那么任何有效证书至少要公开 (k) 个读数。找到恰好 (k) 项的有效证书，就证实最优。这份下界可以由能访问原始记录的复核方重算。对外发放的证书只包含新版标签与需要披露的原始值。

## 在公开 CI 作业上的回放

[事前登记](https://github.com/shuimo233/research-notes/blob/8c69d76cefe30692850ddf243faa8d1194954c5c/articles/consent-audit/slack-certificate-protocol.md)冻结了六个仓库的 72 个公开 GitHub Actions 运行尝试。1,520 个作业中，有 107 个没有凑齐五步完整时间。其余按预设规则抽取 430 个。对每个作业使用秒级步骤开始与结束时刻，以整分钟带和模拟的旧耗时类别归档。新版报告变更步骤耗时、相邻空档以及保留窗口总跨度的分类阈值。[来源清单](slack-certificate-sources.json) · [GitHub 作业时间字段](https://docs.github.com/en/rest/actions/workflow-jobs)

| 方案 | 披露的精确时间戳 |
| --- | ---: |
| 全部披露 | 11,172 |
| 真值揭示前算出的最小固定名单 | 3,710 |
| 保管方逐项选最少追加证据 | 3,417 |
| 保管方反向删去固定名单中多余的证据 | 2,826 |
| 反例集合上的覆盖贪心 | 2,826 |
| 经独立下界证实的最优证书 | 2,826 |

相比最小固定名单，精确披露数下降 **23.83%**。逐项证据法也能省读数，但合计比全局最优多披露 591 项。反向删除已在所有作业达到最优，因而实验未达到相对最佳真值对照再节省 3% 的门槛。证书求解器也在根节点用上下界直接验证了全部最优值，无需展开搜索。例如，ruff 的一项作业含 20 个时间戳，固定方案需 8 个，最短证书和反向删除均需 4 个。[真实作业](https://github.com/astral-sh/ruff/actions/runs/45081753797/job/137394723755) · [完整结果](slack-certificate-results.json) · [逐项记录](slack-certificate-ledger.jsonl.gz)

独立程序直接用原始不等式和 Bellman–Ford 复算 11,172 个标签及所有披露方案，另构造 2,826 份互不重叠的反例来证明逐作业最优。它没有使用生产程序的反例行。450 个小型网络通过逐世界穷举，验证了 3,448 个目标上界和 6,576 个候选读取子集，并核验了 521 份显式替代表。真实时间来自公开 CI，旧与新版报告是模拟的。实验量化精确时刻的披露数，传输成本和隐私强度尚未测量。[独立核验器](slack_certificate_check.py)

## 可运行的保管方和审阅方工具

下面的示例只用标准库。第一条命令在保管方运行，第二条在收到公开证书的审阅方运行。合成示例有六条待核验标签，最优证书只含两个原始读数。第三和第四条可重放完整 CI 实验。

```text
python -I -B slack_certificate_inquiry.py make slack-certificate-example.json slack-certificate-example-readings.json > proof.json
python -I -B slack_certificate_inquiry.py check slack-certificate-example.json proof.json
python -I -B slack_certificate_run.py slack-certificate-fixtures.json.gz reproduced
python -I -B slack_certificate_check.py slack-certificate-fixtures.json.gz reproduced slack-certificate-sources.json
```

采用 Python 3.13 可逐字节复算。输出目录须尚未存在。还可用 `python -I -B slack_certificate_prepare.py raw rebuilt` 读取固定运行尝试的 API 数据并重建快照。API 记录的可用性与内容会随服务时间变化，随文的[冻结快照](slack-certificate-fixtures.json.gz)支持离线重放。独立核验器接受可选的 `--raw raw`，用于核对原始响应哈希。

实例级决定性、用反例集合解释最少证据、以及区间图的线性枚举均有先例。当前的查新问题集中在这一具体结果：对有界整数差分约束，是否已有工作用同一余量结构构造了全部极小反例支持、逐项可验证的替代时间表及紧上界。已查资料尚未找到这个完整构造，全球首创仍待独立核查。[原始文献对照](slack-certificate-prior.md)
