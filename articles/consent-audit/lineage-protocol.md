# 来源关系待核验时的审计 · 实验口径

2026-11-23。在实现和运行本轮实验前记录。给出有限份可能的“报告名到采集根”映射，实际使用其中一份；它在试验期间固定。稳定请求位、已知情境及全程至多 f 个失实根沿用前文。菜单中可购买普通报告，也可购买可信的两报告同源关系检查，后者不占故障额度。优化目标是判定请求是否全零的最坏追加费用。

第一次先例核查已确认，同簇查询、付费决策树和复制来源的真值发现都有直接先例。进一步检验：全零、非零两种解释可以采用不同的来源映射，单个情境的共存条件对应两侧有独立额度的二分图点覆盖。猜测即使每份映射单独足以纠错、只给两份映射，不可判别性仍是 NP 完全的。对有历史、多情境的判别，尝试将一对解释的强制条件化为至多三项的约束，在故障数小的时候求精确证书。第二次查新将按等价的图问题、硬度承诺以及三项约束再检索；已知归约源和标准算法单独归属。

对照将直接枚举小输入上的映射、全真值、可错来源和完整菜单回答，再搜索全部付费决策树；检查费用、首选及不可判定证书。实测使用此前的决策树与逻辑回归，在同一收益档 8、无同意的条件下采集应用、调用入口和 SQLite 授权回调的真实读数。两种归档方式分别复制应用和授权回调，允许单个记录器失实，设计出相同的公开行为日志。比较核对可信归档元数据与读取另一份行为记录的实际读取量，费用是本地夹具的逻辑字节，排除建档与训练。

增项：通过计算搜索找到一个混合策略严格改善最坏费用的小实例，再删去多余操作并由独立完整报告枚举复核。此为有意寻找的反例，不能用它估算实务中的收益分布。另核查三元约束是否可直接换成相同故障变量上的二元约束，不声称禁止其他编码或辅助变量。
