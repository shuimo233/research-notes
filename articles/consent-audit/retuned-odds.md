# 两次发布想少透露一些，最少要改多少旧规则？

同一份时间档案可以回答两种请求。旧系统分别抽取一条真实证词，或返回“未发布”。上一轮保留两类请求原有的全部发布概率，只改变抽签之间的关系。绝大部分目录达不到预先规定的联合赔率目标。本轮保留对外承诺的真实性、最低成功率、标签概率下限和单侧赔率上界，允许调整任一单项概率。每个目标都给出最小调整值或不可行证书。

**21 个原来达不到目标的目录中，只挽回了一个。** 目录 293 至少要改动 $141/2240$，即约 6.29 个百分点，才能将完整观察的最坏赔率比从原独立策略的 $36/7$ 降到目标 $27/7$。逐项复核确认两侧原有承诺仍然满足。两侧同时可答时都保证成功率至少为一半，独立抽签同时拒绝的概率至多为 $1/4$；双方均无合法证词时同时拒绝的概率为 1。因此所有独立策略都至少有 4 倍的联合赔率比，目录 293 的 $27/7$ 低于这个界。[事前协议](https://github.com/shuimo233/research-notes/blob/9d760cfc5a88403ad9535d3f3b8bfb7454d7e2b8/articles/consent-audit/retuned-odds-protocol.md) · [逐项目标](retuned-odds-policies.json.gz)

## 哪些承诺被保留

对每个公开相容的实况 $x$，只给在该实况中真实的证词与拒绝分配概率。两份请求的联合表记为 $p_x(i,j)$，两个单项发布分布由行和、列和得到。两种信息窗口各有自己的赔率上界，合看两条回复还有第三个界。比较同一消息时，只纳入该消息本身仍允许的实况。

联合格子的下限沿用此前已冻结的配对概率下限。某侧有真证词时，服务率至少为 $1/2$，每条真证词至少为 $1/(2k)$。每侧继续满足原先独立核验的最优赔率。给定联合比率 $R$，设 $d$ 为每个实况每项概率相对旧策略的改动上限。把所有边缘概率限制在旧值加减 $d$ 的区间，然后令 $d$ 最小。

对每种观察窗口的每项可见消息，引入跨实况共用的概率下界 $a$。若该窗口的赔率上界是 $B$，把它在每个相容实况中的概率限制在 $[a,Ba]$。令 $a$ 等于各实况的实际最小概率可证明必要性，反向从区间直接得到赔率保证。由于 $B$ 固定，所有要求都是线性约束。求解器可给出明确的概率表及其精确下界，或给出矛盾不等式的非负组合。独立核验器从公开约束重建支持，核对每个窗口的实际赔率和有理数证书。[规划与环流形式](retuned-odds-prior.md)

## 怎样直接发现无法达到的目标

首先用单侧承诺界定可答时的拒绝概率。某真证词 $j$ 若曾是该侧唯一合法证词，在那个实况中它的概率至少为 $1/2$。若该侧赔率上界为 $B$，在任何 $j$ 仍真的实况中，它的概率至少为 $1/(2B)$。把每条真证词的这个界与规定的最低概率取较大值，就能加总出服务率下界，再得拒绝概率的上限。

接着用全空实况和单侧可答实况计算拒绝概率的必要支出。

- 全空实况以概率 1 同时拒绝，因此其他实况必须把至少 $1/R$ 的概率给双拒绝。
- 假设曾有一处左侧必拒绝、右侧的证词 $j$ 可发布。右侧发布 $j$ 的所有概率都落在“左拒绝、右发 $j$”这个配对。其下限由右侧承诺给出；若右侧只剩 $j$，就至少为 $1/2$。
- 对于另一个仍兼容该配对的实况，把这个下限除以 $R$，并与配对原有下限取最大。将这样的必要概率逐格相加，检验它们能否一起装入左侧的拒绝上限。右侧同理。

在冻结的 24 个可测目录和 47 项目标中，**43 项不可行都可以用这个检查排除**，其余 4 项有精确概率表。检查不需要原始时间表或优化器。这是看到本试验结果后的机制诊断，覆盖率仍需跨数据核验。

## 有些目录恰好必须付出乘积

考虑两份公开目录，各含 $k,l\ge2$ 个可独立取真假的整数时间差比较。两侧单项最优赔率分别为 $B_k=(k+2)/2$ 和 $B_l=(l+2)/2$。在左侧全部比较为真时，左拒绝概率被其自身服务和赔率承诺固定为 $1/B_k$。当右侧比较也全为真时，左拒绝概率至少要容纳双拒绝的 $1/R$，再加上右侧每条比较各自的 $1/(2R)$。于是 $R\ge B_k(1+l/2)=B_kB_l$。独立抽签达到此界。

这种冲突允许任意联合随机性和任意边缘重调。提高可调幅度仍无法突破乘积。构造可以直接写成公开整数差约束，并以四组大小核验了可行边界。[完整构造与先例](retuned-odds-prior.md)

## 复算与使用

主判据要求至少五个旧失败在 10 个百分点内挽回，实得一个。47 项证书全部通过独立核验。另用逐对概率约束检查了 42 项小实例和目录 293 的最小改动。Python 3.13 和 SciPy 1.16.3 用于重求；核验和发布仅用标准库。[结果](retuned-odds-results.json)

```bash
python -B retuned_odds_run.py denial-odds-policies.json.gz joint-odds-policies.json.gz replay
python -I -B retuned_odds_check.py denial-odds-policies.json.gz joint-odds-policies.json.gz replay
python -B retuned_odds_boundary_check.py denial-odds-policies.json.gz joint-odds-policies.json.gz replay/retuned-odds-policies.json.gz
python -I -B retuned_odds_inquiry.py check denial-odds-policies.json.gz joint-odds-policies.json.gz retuned-odds-policies.json.gz --index 16
```

目录 293 对应索引 16。获准的保管方可把最后一行的 `check` 改成 `publish`，加入 `--record local-timestamps.json --sealed-file private-pair.json --side left`。服务右侧时改用 `--side right`，并复用同一个场景的私有缓存。每次对外只返回一侧；完整配对由保管方持有。
