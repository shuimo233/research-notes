
# 直接优化每批档位次数，能否同时省分桶和尾部时间？

这轮在开表计时前求出了每批的档位次数，再将档位随机分给已通过审计的请求。**有效宽度种数减少了约 4.92% 和 4.97%，P95 耗时下降了约 0.41% 和 3.88%。** 两轮都未达到预先登记的 5% 主门槛。新增六个计时目录通过了不退化门槛，其 P95 分别变化约 +0.74% 和 −1.96%。 [冻结协议](https://github.com/shuimo233/research-notes/blob/0a41c07e3ca6d522aff455ee996b1ec413206e1c/articles/consent-audit/audit-runtime-histogram-protocol.md)

## 把工作量上界放在优化里

用已核验的分组，每批仍有一半概率逐项独立抽档。另一半选择每组的档位计数，再随机分给请求。同组位置可交换，不同组的抽签独立。八个等概率档位在计数分布上的期望次数相同，因此每项的档位边缘与基线一致，原整窗归一全拒绝保证继续成立。

选计数表只用三个已声明实况的实际词元长度和预先选定的档位。对给定计数表，有效宽度为原长度与档位的最大值。把长度从短到长、档位从长到短配对，可以精确求出任意排列下最大的有效宽度总和与平方和。各组的上界相加，得到整个批次的界。优化器要求，在每个实况里，计数分支的这个上界至多为逐项独立工作量的 P90。由于独立分支只占一半，混合后的两个工作量代理的 P95 均不超过该实况独立基线的 P90。

目标是最少的期望有效宽度种数。给定计数表，某个宽度是否出现可以用组合计数求出。把这个宽度的重复档位分配给比它更长的请求，再给恰好同长的请求配上更长档位，便得到它缺席的概率。组间独立，缺席概率相乘。优化器枚举协议指定的互补表，独立检查器用另一种计数顺序复核了可行性和最优性。18 个目录中有 **11 个找到可行表**，另外 7 个回退到逐项独立，全部计入汇总。 [证明和已知工具](audit-runtime-histogram-prior.md) · [精确优化器](audit_runtime_histogram.py) · [逐目录计划](audit-runtime-histogram-plans.json)

## 实测保留的取舍

回放把八个批次和八个档位连成二分多重图。每批保留已选档位次数，每种档位的整轮次数相同。将这个图分解为完全匹配并把每条匹配交给一项请求，就能保持每题在整轮各档同频。两轮均逐题配平。实际使用同一个 CPU 会话，按有效宽度分桶。5,184 项计时中的 **124,416 个模型分数**逐位符合此前冻结的单独执行结果。

| 调度 | 两轮每批平均有效宽度种数 | 两轮 P95 耗时 |
| --- | ---: | ---: |
| 逐项独立 | 6.072 / 6.083 | 54.049 / 51.883 ms |
| 等层分配 | 5.880 / 5.870 | 52.090 / 49.053 ms |
| 优化档位计数 | 5.773 / 5.781 | 53.825 / 49.873 ms |

优化计数在两轮里都比同场的等层方案更省分桶。等层方案的 P95 更低。优化计数相对逐项独立的配对中位耗时比是 0.996 和 1.002。工作量上界与按宽度算出的分桶成本可以分别核准，墙钟收益需要实测。离线求解和预热均在计时前完成。这一轮的结论限于固定模型、名义档位分布、这台 CPU 和已声明回放。 [原始纳秒记录](audit-runtime-histogram-trace.json.gz) · [全部汇总](audit-runtime-histogram-results.json)

已有的有限交换序列、平衡抽样、负相关工作量分配和二分图匹配为方法提供了直接依据。候选贡献是把有效宽度缺席计数和最坏工作量同时纳入保持整窗拒绝保证的路由规划，并用逐题配平计时刻画量化工作约束与真实尾部的差别。相关先例和有限查新的边界已记录。 [查新](audit-runtime-histogram-prior.md)
