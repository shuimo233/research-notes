# 零次未经同意的写入，能说明代理尊重同意吗？

2026-11-23

续篇已把同一问题扩展到看过读数再选下一次报价，并用独立的决策树穷举和新采集的区间历史核验。[已有历史时的最优顺序审计](sequential.md)

两个分类器看了相同的八个示范，也都学对了八次。让它们在 20 档收益下分别面对有同意和无同意两种情境。数据库最终给出完全相同的记录：各有 20 次获准写入，未经同意写入均为零。但是，一个模型从来没有在无同意时发出写入请求，另一个在收益第 8 至 20 档都试过，13 次全被执行闸拦下。

这个差别能从证据中恢复到什么程度？我们做了一个标准库命令行工具。它读取闸前请求和闸后效果，列出仍与历史相容的阈值。在给定的部署收益范围内，它同时计算采用和撤销单调性假设所需的审计预算。证据不足时，阈值模式会给出两个能解释记录、却会在指定条件下做相反选择的行为规则。[工具源码](consent_audit.py) · [完整实验数据](learned_results.json)

## 这次观察的是哪一件事

“请求”指代理调用受保护操作，不包含它向用户征求许可。实验的收益是模型收到的正整数输入。“部署范围”是需要报告结论的输入范围。系统另外记录实际有无同意，SQLite 授权回调决定操作能否写入本地表。表里只有合成的报价和同意位，实验中没有向外部收件人发送内容。

我们把“尊重同意”缩小为一个可审计的行为命题：在同一决策环境、相同上下文、部署允许的每一档收益上，只要无同意，代理都不会发出该请求。它涉及未发生情形，强于过去没有成功写入。它也有明确的解释限度。一个知道执行闸必会阻止写入的代理，出于节省调用成本就可能拒绝全部请求。即使读得到请求位，也需要额外证据才能把沙盒结论迁移到撤掉执行闸的环境。本文不从调用记录推断道德动机。

## 两个学习器与同一份日志

两者的输入均为同意位和收益。有同意的示范收益为 3–6，没有同意的为 1–4，标签等于同意位。两模型各训练一次，未按结果调参。执行时用文件数据库和 SQLite 的授权回调拦截实际 INSERT，关闭语句缓存以保证逐次调用都会经过授权；关闭连接后从新连接读回。随后按审计工具的方案，额外独立做一次收益 20、无同意的闸前观测。[实验脚本](learned_demo.py) · [实验口径及增项时间](PROTOCOL.md)

| 实测 | 深度上限 2 的决策树 | 标准化后拟合的逻辑回归 |
| --- | ---: | ---: |
| 训练预测正确 | 8/8 | 8/8 |
| 无同意时发出请求的收益档 | 无 | 8–20 |
| 主实验中真正发生的无同意写入 | 0 | 0 |
| 新做的收益 20 闸前试验 | 拒绝 | 请求，被拦 |

事后可以打开模型交叉检查：这棵树唯一的分裂使用同意位。逻辑回归在原始收益单位上的系数约为 0.367，所以即使同意位取零，报价也能将它推过决策边界。模型结构给出了独立于日志的解释。训练示范是合成数据，分类器输出是实际运行结果，本次没有用大语言模型或人的道德判断作样本。

## 一次闸前试验，还是二十次？

只看上述 40 条执行效果，两个模型都与“无同意时始终拒绝”相容。在无错读、收益为 1–20 的条件下，结论取决于允许的其他解释。

- **若请求随收益单调。** 在最高档仍拒绝，就覆盖了这 20 档；在最高档请求，就足以反驳全范围拒绝。一条闸前试验能区分这两种行为结论。即便最高档拒绝，也仍可能在更高档才开始请求。
- **若只要求同一报价重复时响应稳定。** 一个只在第 7 档请求的规则可以通过那条最高档测试。每一档都有这样的单点例外。初始日志全是闸后效果时，要排除全部例外，20 档各要一次精确的闸前观测。树在第 20 档拒绝后，还剩 19 档需要覆盖。对于回归模型，第 20 档那一次实际请求已经反驳了全范围拒绝。

这 19 次差额量化了**有多少结论来自模型假设**。它不表示现实里任一个系统都应测 20 次；它给的是此例在两组明确假设下的最小固定试验数。若系统会记住之前的试验、随机行动、依据提示措辞改变行为，或把审计用的收益与部署时的收益区别对待，应重新定义比较对象。

## 带错读时，哪些试验真的还需要做

我们推导了一个更窄的结果。报价属于有限整数集合，历史试次的实际报价可以只知道一个区间，每个试次单独取值。整个历史与未来共允许最多 $f$ 条试次记录被替换。若全拒绝规则尚与历史相容，即使允许每一档收益都有独立的请求行为，计算最低审计费用时，**逐档考虑“只在这一档破例”的规则就充分了**。多个档位一起破例不会增加必须购买的试验。对任意一档，未来报价区间有正宽度的试验不能保证击中单点，因此也不能降低最优费用。具体每档需要几次取决于它能解释哪些历史记录，而非一律重做 $2f+1$ 次。[公式、假设及完整证明](proof.md)

工具另给出阈值假设下的最便宜固定追加方案。例子中部署上限是 10，过去在报价 6 时记下过一次被闸拦住的请求，日志总共允许出错一次。报价 6 的试验成本为 1，报价 10 的为 5。最优方案是两种试验各一次，总成本 6。撤去单调假设，同一记录要求在报价 6 观察两次，在其他九档各观察一次。现有菜单只有两种报价，无论重复多少次都无法完成后一个任务。[可直接输入的例子](example.json)

工具对 480 个固定种子问题和 48 个系统组合逐一与独立枚举比较。枚举器展开全部小规模行为函数、菜单子计划和未来可见的联合日志，检查通过的计划能否真的区分两组解释以及费用是否最低。另在 108 个有历史错误预算的问题上，针对全部三档行为函数和全部精确报价采购量，专门核对了单点配额。数值核验支持实现的正确性；一般情形的结论依赖证明。[独立验证器](check.py) · [验证记录](validation.json)

## 与前人工作的边界

有限报价无法区分绝对原则与足够大的有限权重、运行时屏蔽可以掩盖原始动作、纠错需要足够的区分次数，均有明确先例。阈值模式的成本最优化也能由已有的拟阵贪心方法推出。可供审查的候选贡献，是**在区间报价、联合日志和跨历史的总错误额度下，撤去单调性后仍由历史相容单点例外给出精确费用的命题**，以及将这一费用与单调假设并列交付的工具。本轮核查未找到直接给出同一历史条件公式的原文，尚不能确认全球优先权。[按主张列出的原文与检索边界](precedents.md)

## 使用

复制同目录的 `consent_audit.py` 和 `example.json`，运行 `python -I consent_audit.py example.json`。审计器只依赖 Python 标准库。输入里的 `request: null` 表示没有闸前读数；`effect` 是本次操作的执行效果。菜单条目都代表无同意、保证取得闸前请求位的试验，`low/high` 为可保证的报价区间，`capacity` 为可用次数，`cost` 为单次费用。每个试次最多计一次错误。若一种规则预测的请求或效果与记录不符，该试次会耗用一个错误额度。

`status` 是阈值类内的结论。`absolute_veto_compatible` 只表示绝对规则尚能解释记录。`without_monotonicity` 单独报告撤去单调性后的结论。在其适用条件外会标出越界历史或安全基线已被排除，后一状态不承诺另一行为规则必然与日志相容。`reported_unauthorized_effect_trials` 列出实际记录为无同意且有效果的试次（从 1 开始）；有独立证据确认的真实写入应按实际事件处理。`separating_exact_offer` 区分的是所列两条规则在无错读时的响应，能承受全部允许错读的方案见 `additional_plan`。

在本目录运行 `python -I -B check.py` 可复现穷举验证；在安装 scikit-learn 的环境中运行 `python -B learned_demo.py` 可重新拟合两个模型并执行数据库实验。本次实测使用 scikit-learn 1.8.0、SQLite 3.49.1。
