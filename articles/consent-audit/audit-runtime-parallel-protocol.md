
# 冻结协议：在同一推理语义下比较算子内并行和请求任务并行

复用已审计的 SNLI 请求分组、逐项分数与逐行补齐图。固定 Git 对象为 09efe9dbdb03c0826bfc884e6cc2228ebbd551b8 和 06cc9ac4fa4c04dff0b840475c5c0a34c3be5595，图 SHA-256 为 595bfd653973f8065c9e31cac909b5646f5cf4e0c8964c5c8683445b732f08fe。每次执行都必须逐位重现对应输入档位的冻结分数。

## 三种可执行方式

三种方式采用同一 ONNX Runtime CPU 提供器，各会话的 inter-op 为一，顺序执行模式，并关闭空闲算子线程自旋。最多配置四个执行图的线程。主机侧使用会话复用和预热的常驻工作池。

- 旧式算子内并行。按有效宽度分桶，顺序发起各桶调用，每次使用 intra-op 为四的会话。
- 宽度桶任务并行。同样分桶，四个工作线程向同一 intra-op 为一的会话并行提交不同桶。
- 均衡任务并行。有效宽度按平方估计工作量，按最长任务优先规则分到至多四个任务。任务数也不得超过该批的不同有效宽度数。每个任务一次调用同一 intra-op 为一的逐行补齐会话，可包含不同宽度，最终按原请求位置回填。工作估计固定，不根据实测调参。

执行改变发生在每项档位选定之后。已审计的逐项调度和分层调度各作一套输入，三种执行方式在相应输入上接收完全一样的词元和档位。端到端比较以逐项调度的旧式算子内并行为现实对照。两份会话的启动、工作池创建和预热均排除在计时外。

## 实测和验收

既有计时目录为 0、12、24、34、48、59，首次计时的目录为 1、7、13、22、42、58。取三个实况及零分差门槛，种子 7655548，做两轮。每个目录及实况每轮 16 批，前 8 批复用同一逐项档位向量，后 8 批按各自方式生成配平路由。每轮每题每档使用两次。每个批次单元六种组合轮换先后，共 6,912 项计时。计时包含任务分配、输入整理、核验、推理和结果回填，排除分词、抽档计划和分数对照。另记实际调用次数与进程 CPU 时间。

主要比较是分层加均衡任务相对逐项加旧式算子的端到端表现。两轮的 P95 时延、实际调用次数均值之比都须至多 0.95，配对中位时延之比须至多 1.05。首次计时目录另以两轮 P95 不高于对照 1.05 倍为复验门槛。两套输入内同时逐项比较三种执行方式，核对节省来自并行、合并调用还是两者。保留全部时延、CPU 时间与负结果。这轮不改写此前只优化路由时的验收结果。
