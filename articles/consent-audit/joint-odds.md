# 两类请求分别安全，合起来还会多透露什么？

两个审阅者各自可以从同一份私有时间表取得一条真实证词，也可能只收到“未发布”。就算两份请求分别具有经过核验的发布规则，两位审阅者合看消息时，赔率变化也可能比单独看大得多。这里固定每类请求原有的全部概率，只改变两次抽签之间的关系。

24 个可测目录中有 2 个能把双次观察相对单次观察的额外赔率放大至少减半，低于事前要求的 5 个。失败有一个可直接计算的原因。**当不同实况固定了多个输出配对时，更小的联合赔率上界可能迫使它们在同一实况中占用太多拒绝概率。** 这个检查解释了全部 21 个未达到减半目标的目录。[事前协议](https://github.com/shuimo233/research-notes/blob/0a1b7b24902f5806bfc572bd7254f96e9dba0510/articles/consent-audit/joint-odds-protocol.md)

## 同一份联合表保留两种原有服务

对每个可行实况 $x$，两类请求的原始发布概率分别为 $\mu_x$ 和 $\nu_x$。两边输出都包括可见拒绝。联合概率 $P_x(i,j)$ 的行、列和必须分别等于 $\mu_x(i)$ 和 $\nu_x(j)$。两类请求各自获得同样的真实证词概率、拒绝概率和最低服务率。每个两边分别允许的配对仍须有正概率。试验的下限 $f_{ij}$ 是独立策略在该配对兼容实况中的最小概率的一半。

完整输出的最坏赔率比比较同一个配对在所有兼容实况中的概率。它刻画看到该配对之后、除了两条证词实际为真以外，发布规则对相容实况的额外区分。只看其中一个输出时，适用该边原有赔率比。这两种观察窗口的上界应取最大值。有些配对本身会缩小相容实况的范围，于是完整配对的比率也可以低于单侧比率。

给定要验收的比率 $R$，为每个配对引入全局下界 $a_{ij}\ge f_{ij}$。局部运输表的每个格必须落在 $[a_{ij},R a_{ij}]$ 内。取各格在相容实况中的最小实际概率即可证明必要性；每个实况都能满足该区间和边缘时，组合起来就得到一套达标发布规则。

用带上下容量的运输割来找出矛盾。设 $I,J$ 是所选的行、列集合，边缘总质量之差必须满足

$$
\mu_x(I)-\nu_x(J)
\;\le\;
R \sum_{i\in I,\,j\notin J} a_{ij}
-
\sum_{i\notin I,\,j\in J} a_{ij}.
$$

式中的求和只用当前实况兼容的行、列。减去各格下界后，行有剩余供应、列有剩余需求，配对的剩余容量为 $(R-1)a_{ij}$。最大流最小割给出充分性。求解程序按需生成违反的割。成功时保存有理数联合表，失败时保存一组割的非负组合，独立核验器只需检查有理数不等式。[联合表和不可行证书](joint-odds-policies.json.gz)

## 先看拒绝概率够不够

甚至可以先做一个不求解运输规划的检查。减去每个格的下限 $f_{ij}$ 后，记实况 $x$ 的行、列剩余为 $r_i,c_j$，总剩余为 $h$。此时一格的最小可能值为

$$
\ell_{x,ij}=f_{ij}+\max(0,r_i+c_j-h).
$$

目标为 $R$ 时，任何允许该配对的实况都不得把其概率降到 $\max_x\ell_{x,ij}/R$ 之下。再与原定的格子下限取最大。若这些必要概率在某列的和比该列的已定边缘概率还大，目标不可达。逐格也可同理比较必要概率与其最大可行值 $f_{ij}+\min(r_i,c_j)$。这项拒绝检查的算术操作数与所有实况里的兼容配对总数成正比。通过检查的目录仍须生成联合表。

以拒绝列为例，某些实况里第二种请求没有真实证词。第一种请求一旦发布证词 $i$，与之配对的只能是拒绝，所以该配对的概率等于第一种请求发出 $i$ 的概率。不同实况可以分别固定不同的 $i$。当其中多个 $i$ 在另一个实况同时为真，它们配上拒绝后的必要概率必须一起装进第二种请求原有的拒绝概率。

## 回放结果

从 25 份冻结的 BART 公开目录按事前规则生成两种关于不同事件的请求，1 份目录只产生一种请求。两个边缘发布器都保证在有真实证词时至少有一半机会成功。无须读取实际时间表，独立程序重建 629 种可行的成对模式，核验了 47 项不同的目标。此前验证过的边缘发布策略来自[可见拒绝研究](denial-odds.md)。

| 检验 | 结果 |
| --- | ---: |
| 独立双次抽签比最坏单侧观察泄露更多 | 23 / 24 |
| 将额外倍率至少减半 | 2 / 24 |
| 仅靠双方均拒绝的单格概率排除单侧上界 | 23 / 24 |
| 通过拒绝行或列的概率和排除减半目标 | 21 / 24 |

目录 250 和 335 的联合赔率比由独立时的 9 降到可验证的 6，单侧最坏比率仍是 3。两种更简单的对照方案分别共享或反向共享决定是否回答的随机数，再以一半概率与独立策略混合。这两种方案在这两个目录的联合比率均为 12。诊断是试验结果出来后做的，并在同一数据上复核；其跨数据适用范围仍待验证。[结果](joint-odds-results.json)

## 使用与复算

Python 3.13 和 SciPy 1.16.3 可重生成联合发布证书。独立核验器与实际发布器只需 Python 标准库。边界测试还用直接的逐实况概率规划复核了 63 项小实例。

```bash
python -B joint_odds_run.py denial-odds-policies.json.gz replay
python -I -B joint_odds_check.py denial-odds-policies.json.gz replay
python -B joint_odds_boundary_check.py denial-odds-policies.json.gz replay/joint-odds-policies.json.gz
python -I -B joint_odds_inquiry.py check denial-odds-policies.json.gz joint-odds-policies.json.gz --index 11
```

目录 250 对应索引 11。将最后一行的 `check` 改为 `publish`，加入 `--record local-timestamps.json --sealed-file private-pair.json --side left`，输出左边请求的结果。服务右边请求时，使用同一记录、配置和私有缓存文件，参数改为 `--side right`。缓存包含两边的结果，由保管方持有。每个接收方只得到自己的分量。同一场景的重试复用该配对，目前的保证覆盖这固定的一对请求。

保留各次发布边缘、通过相关随机数减少合看时的泄露已有直接先例。运输割也是经典结果。本轮值得继续核对的增量是可见拒绝与真实配对下限同时存在时，怎样用简单的概率预算解释无损发布为何不可行。另有一个更严格下限下的二元分界，两个世界的独立抽签已最优，三个世界才可能严格改善，而且最优比率可以是无理数。[无损多次发布](https://proceedings.mlr.press/v267/andersson25a.html) · [二元分界与原文核对](joint-odds-prior.md)
