# 审阅者也能看到拒绝，发布规则还能保证什么？

假设审阅者要从一个公开目录里取得一条真实的时间差证词。保管方只能发布在实际时间表上成立的证词。有些相容时间表上没有任何合法证词，保管方只能说“未发布”。如果所有可以发布的情况都一定发布，那么一次“未发布”就足以断定没有任何合法证词。这一轮把“未发布”也纳入对发布规则的审计。

给每种能够发布的实况设定最低成功率 $s$，并规定每条真证词都有至少 $\alpha$ 的发布概率。我们得到一个精确的线性规划，可以同时优化证词和未发布消息的赔率上界。在冻结协议的 BART 主试验中，25 个目录有 24 个严格优于该目录下任何恒定成功率的规则。[冻结协议](https://github.com/shuimo233/research-notes/blob/72bd26cf5cd628695e3165903da9333d5dc8b299/articles/consent-audit/denial-odds-protocol.md)

## 一次输出对推断的影响

令 $S(x)$ 为相容记录 $x$ 下真实的证词集合。看到证词 $j$ 会排除 $j$ 不成立的记录。对于其余任意两条记录，发布规则额外改变它们相对赔率的倍数，等于 $p(j\mid x)/p(j\mid x')$。看到“未发布”时，两条记录可以任选，包括没有合法证词的记录。目标是同时约束这些比率。

这个定义限定在一次固定场景的公开消息上。它允许发布内容本身揭示证词为真，也允许拒绝概率在实况间有界地变化。多次独立抽样、时延和公开目录的形成过程是不同的观测。

## 精确最优策略

用 $r$ 表示所求最坏比率的倒数。只需给每个证词一个权重 $a_j$，并解下面的规划。非空 $S$ 遍历公开档案允许的所有真实证词集合。

$$
\begin{aligned}
\max\quad &r\\
0\le r&\le1-s,\qquad a_j\ge\alpha,\\
sr\le A_S&\le1-r,\qquad A_S=\sum_{j\in S}a_j.
\end{aligned}
$$

任何达标规则都可以用每条证词的最小发布概率作为 $a_j$。要使该证词的赔率放大至多 $1/r$，其每个发布概率必须在 $[a_j,a_j/r]$ 内。空模式的拒绝概率为 1，所以任何非空模式的拒绝概率都至少为 $r$。合计发布概率至少为 $s$、至多为 $1-r$，给出上述约束。

反过来，在每个非空模式以 $u_S=\max(s,A_S)$ 的概率发布，并按 $a_j/A_S$ 在真证词中抽取。保留剩余概率给“未发布”。由约束得 $u_S\le1-r$，以及 $1\le u_S/A_S\le1/r$，因此两个类型的最坏比率都至多为 $1/r$。这也给出了达到最优值的运行规则。

给定最优值 $r^*$ 后，任何恒定发布率 $c$ 要想追平，必须满足 $s\le c\le1-r^*$。在这个区间内，$c$ 越大，条件发布后每条证词需要满足的概率下限 $\alpha/c$ 越低。因此在最大的 $c=1-r^*$ 下求一次精确的[条件发布规划](selection-odds.md)，即可判定所有恒定发布率是否都较差。在四条证词的一维整数例子中，最优浮动服务率得到 $10/7$，而最优恒定服务率是无理数，给出约 $1.547$ 的赔率比。完整推导还给出任意目录的严格改善条件，以及从简洁的差约束表示出发时的复杂度边界。[推导、反例与先例](denial-odds-prior.md)

## 冻结目录的对照

25 份目录来自此前冻结的 BART 换乘档案。每份目录以 $\alpha=1/(2k)$ 固定单条证词的无条件概率下限，$k$ 是证词数。独立程序从公开差约束重建了 626 个非空模式，核对了每份目录的空模式，以及全部 75 项的实际概率与精确最优性。整个核对只需公开输入。主试验事前要求最低发布率 $1/2$ 时至少五项严格改善，实得 24 项。

| 最低发布率 | 严格优于任意恒定率的目录 | 浮动策略的跨目录最坏比率 | 固定在最低率的跨目录最坏比率 |
| --- | ---: | ---: | ---: |
| $1/4$ | 24 / 25 | $35/13$ | 25 项都不可行 |
| $1/2$ | 24 / 25 | $4$ | $10$ |
| $3/4$ | 6 / 25 | $11/2$ | $6$ |

在主试验的目录 250、273 和 335，每条证词均有只它成立的模式，另外存在六条证词同时成立的模式。任何恒定率规则在单条模式上都必须把全部服务概率给那条证词，在六条同时成立的模式至少有一条的概率只有其六分之一或更低。因此恒定率策略的最坏比率至少为 6，固定 $s=1/2$ 已达到 6，浮动策略精确达到 4。[逐项证明](denial-odds-policies.json.gz) · [结果](denial-odds-results.json)

## 复算与发布

在本文目录执行以下命令。生成器使用 Python 3.13 与 SciPy 1.16.3。核验器和发布器只用标准库。独立的直接概率规划另外检查 78 项小实例的可行边界。

```bash
python -B denial_odds_run.py selection-odds-policies.json.gz replay
python -I -B denial_odds_check.py selection-odds-policies.json.gz replay
python -B denial_odds_boundary_check.py replay/denial-odds-policies.json.gz
python -I -B denial_odds_inquiry.py check denial-odds-policies.json.gz --index 0 --service 1/2
```

保管方可将最后一行的 `check` 改成 `publish`，并传入 `--record local-timestamps.json --release-file local-release.json`。输入是按公共档案编号排列、锚点为 0 的本地整数数组。为同一个固定场景使用同一发布文件，首次结果写入后，重试读回该结果。拒绝由同一格式记录，空模式的必然拒绝与随机拒绝会产生完全一样的消息字节。测试覆盖了这两条路径、精确抽样与并发重试。

已有查询审计研究明确指出，拒绝可能泄露记录信息，也用应答率衡量服务效用。共同输出上的似然比同样已有研究。此处可复核的增量是同时满足真实性、逐实况最低服务率和可见拒绝时的精确最优规划，以及何时严格胜过所有恒定服务率的判定。当前实验覆盖来自同一来源的 25 个冻结目录，查新结论以所核对的文献为界。[拒绝泄露研究](https://theory.stanford.edu/~nmishra/Papers/denialsLeakInformation.pdf) · [共同支持上的隐私损失分布](https://www.petsymposium.org/2019/files/papers/issue2/popets-2019-0029.pdf) · [相关工作核对](denial-odds-prior.md)
