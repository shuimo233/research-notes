# 同一个词义只问一次，一句话能少问多少？

SemEval-2013 的一个句子里，team 出现两次，两处都与同一个 group 构成待判断的词对。只要确认这处 group 指由成员组成的集合，team 的两个候选名词义项都属于它。这一个回答就够确定两项关系。两处 team 仍是不同的词元，只有同一位置的 group 共用回答。这个已看过的例子，在计算整句的询问次数之前就写入了公开方案。[事前方案](https://github.com/shuimo233/research-notes/blob/3210404d781a20cb5626728c0110aae76b7036ca/articles/consent-audit/shared-sense-protocol.md) · [逐词对测量](wsd-clarification.md)

## 最大的一笔节省来自哪一步

我们在已冻结的两个词义标注集合里，找出同句至少两个判断共用某一词元的所有句子。WSD 用先前广集合的单金标行；SemCor 只取两个词元均有多种名词义项的行。对每个句子，系统都必须给出全部词对的正确词典关系。各个位置只揭示一次，只有在每一种剩余解释都给出同一组结果时才能停止。题目的关系范围、成本与比较方法在计分前固定。[两套语料的逐句与逐步账本](shared-sense-ledger.jsonl)

| 同句共享词元的样本 | 各词对独立询问 | 缓存后四种顺序中的最低总数 | 最小覆盖优先 | 优先选择预计能立即解决最多判断的词元 | 逐句最少询问数之和 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 外部 WSD，60 句、192 项判断 | 259 | 164 | 162 | **159** | 149 |
| SemCor，39 句、132 项判断 | 173 | **84** | 86 | 85 | 81 |

在 WSD 上，相对独立询问，缓存并采用四种固定顺序中表现最好的一种省了 95 次。保持逐对查询的关系表策略及正序，仅加上共享记忆，就从 259 降到 168，单这一改动省了 **91 次**。SemCor 的同一改动从 173 降到 86，省了 **87 次**。缓存的效应在两个集合都出现。进一步改变整句的询问顺序，WSD 上最小覆盖策略比最好的带缓存顺序再省 2 次，达到预登记的主判据，但另一个简单的贪心顺序还要再少 3 次。SemCor 上覆盖策略比最好的带缓存顺序多问了 2 次。[四个固定顺序、两种整句策略和完整计数](shared-sense-results.json)

表中固定顺序的最低总数是先在整个样本上分别运行四种策略再取最小值。没有用正确义项为每个句子挑效果最好的对照。若计入全部句子，WSD 覆盖策略用 350 次，最低固定顺序用 349 次；SemCor 分别是 281 与 258 次。覆盖策略的经验优势只出现在预登记的 WSD 共享词元子集。单句间同一拼写或同一 lemma 都不能复用义项。计量的是准确揭示词义的次数；没有测人读取候选释义的时间。[两集合的全部句子](shared-sense-results.json)

## 怎样知道一个句子最少必须问几次

给定一个句子的真实解释，观察哪些已知词义足以使剩余每个可能解释都给出相同答案。对一条非常量关系，只有四种情况。两端分别单独揭示都不够，就必须问两端。只有一端能单独定案，就必须问那一端。两端中的任一端都能单独定案，就必须至少选一端。原本就是常量的关系无需询问。把所有必须问的位置先收入集合，对尚未满足的二选一要求，在它们组成的图上取最小顶点覆盖，即得到整个句子的最小证书。每个局部要求都是必要条件；所有局部要求一起满足，整组输出就已确定。这里假设词元候选义项可以独立组合。[已知最优验证集定理及与本问题的对应](shared-sense-prior.md)

这个逐句最小值要用真实解释来算，是评估在线策略的下界。实际运行的覆盖策略先在所有非常量词对间求最小覆盖，再根据已有回复跳过已经无关的位置。第一阶段花费不超过最小覆盖大小，而任何准确证书都至少要覆盖这些边。第一阶段结束后，每条仍未决的边只剩一个未知端点；它在对端实际义项已经固定时仍然能改变输出，即使知道其他所有位置也不能略去。因此第二阶段的每次询问也都是任何实际证书必须支付的。两阶段加起来至多花逐句最优的两倍。我们采用了已有的查询框架，没有把这个两倍界算作新的数学发现。[不确定区间排序的两倍策略](https://arxiv.org/abs/2012.09475) · [图上的最优验证与概率加权覆盖](https://arxiv.org/abs/2107.00572)

在外部 WSD 的 60 个共享句子里，覆盖策略在 48 句达到最少询问数，最差的一句用了下界的 5/3。SemCor 的 39 句中有 34 句达到最少，最大比值为 3/2。精确求最小覆盖在大图上可能昂贵；这里被核查的句子最多只有 11 个待澄清位置。研究产物是可运行的词义询问服务、冻结的同句任务与可以逐句核验的成本对照。查新所见的直接理论先例和相关词义研究收在同一份笔记中。[核验数据](shared-sense-checks.json) · [先例核查](shared-sense-prior.md)

## 试用

输入由位置 ID、该位置的词和待判断的有序位置对组成。这个示例只抽取开头句子里的两个判断。第一条命令请求 group 的义项并列出候选释义。第二条给出该词元的义项后，两个判断都返回 `right_narrower`，即对应位置的 team 是 group 的严格下位。自己的句子也可按同样的 JSON 格式传入。包默认按最小覆盖排程，也可用 `--policy greedy` 或四种带缓存的逐对顺序。[示例输入](shared-sense-example.json) · [查询入口](shared_sense_query.py)

```sh
python -I -B shared_sense_query.py wordnet-3.0-nltk.zip shared-sense-example.json
python -I -B shared_sense_query.py wordnet-3.0-nltk.zip shared-sense-example.json --sense group=00031264
```

重跑时先准备前次实验固定的 WordNet 3.0 压缩包，使用本目录发布的两份输入账本。第一条命令生成新的结果目录；第二条用另一套 WordNet 接口重建词典关系与两个语料的批次，穷举全部 7,032 种逐句位置子集，检查证书最短性，并重新推导 2,070 条六种策略的轨迹和终止条件。一共涉及 345 句、576 项关系。[生成器](shared_sense_run.py) · [独立检查器](shared_sense_check.py) · [公开检查记录](shared-sense-checks.json)

```sh
python -I -B shared_sense_run.py wordnet-3.0-nltk.zip fresh-shared
uv run --no-project --python 3.13 --with nltk==3.9.2 -- python -I -B shared_sense_check.py wordnet-3.0-nltk.zip fresh-shared
```
