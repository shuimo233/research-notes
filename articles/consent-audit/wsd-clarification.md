# 确认“这是一种什么”有时也能少问一次

在 SemEval-2013 的一处标注中，group 指若干成员构成的集合，team 指协作小组。即使对方只确认了 group 的这个义项，WordNet 中 team 的两个候选名词义项都能沿严格上位链到达它。因此可以答“team 是一种 group”，并结束询问。这是上一轮 SemCor 里未观测到的正例。它也说明，评估一个推理系统的节省来自哪里，需要保留逐项来源。[逐项记录，编号 semeval2013.d001.s001](wsd-clarification-ledger.jsonl) · [前次 SemCor 结果](semcor-clarification.md)

## 原样复验的样本不够

我们在读取外部逐词文件前，公开登记了两个集合与判据。Raganato 等统一的五套英语 WSD 评测共有 26 篇文档、1,173 句、4,300 个名词目标。全部目标的金标义项都能映射到固定词典。从前次的 208 个双向词对出发，仅找到 **2 处**同句共现。一处是 minute/time，完整语境的两个义项之间没有严格上下位关系；另一处是 change/difference，有两种可接受的义项组合。预定条件至少需要 20 个单金标严格上下位正例，此处是零。因此这组数据不能确认相同选词规则下的 SemCor 观察。[查分前的方案](https://github.com/shuimo233/research-notes/blob/9c700fc6e13bef0c8042f47e77dcc2a1e54237eb/articles/consent-audit/wsd-clarification-protocol.md) · [原始评测的设计和来源差异](https://aclanthology.org/E17-1010/)

## 改变问题，哪部分成本才会动

对同一批词和同一批义项，我们另外问三个二元问题。表中每列都重新计算何时可以停止。

| 服务需要返回什么 | 可执行的关系表策略，324 处合计 | 逐例最短证书合计 |
| --- | ---: | ---: |
| 同义项、甲下位、乙下位、均非，四选一 | 444 | 389 |
| 甲是否为乙的严格下位 | 233 | 211 |
| 乙是否为甲的严格下位 | 208 | 177 |
| 是否存在任一方向的严格上下位 | 439 | 386 |

前两个定向问题总数大幅下降，却都无法让各自回答“是”的实例拥有更短的证书。原因可以直接证明。设原判断为 $f$，新问题问 $f$ 是否等于某个特定值 $v$。在真实答案为 $v$ 的世界里，一组已揭示事实足以答“是”，当且仅当所有与它相容的世界都给出 $v$；这恰好也是它足以确定原判断为 $v$ 的条件。因此这两种问法的肯定证书完全相同。这个事实也适用于有任意多个输入的确定性判断。它来自标准的证书定义。实际选择顺序的策略仍可能给出不同长度的路径。[决策区域与证书先例](wsd-clarification-prior.md)

“任一方向都算”合并了两个肯定类别，前面的单类别论证对它没有约束力。但在这里 65 个严格上下位正例的最短证书仍全部持平，未出现事前设想的正例额外收益。对于维护推理接口的人，这两个数字应分别保留：更窄的提问能节省总体交互，最需要肯定依据的那批请求能否随之获益，要看各自证书。[四种问题和 65 个正例的逐项对照](wsd-clarification-results.json)

## 多种金标与复现

43 处多金标组合中，有 33 处无论选哪个可接受义项都得到同一四类关系。服务在事前仍须考虑词典里的所有候选。四类判断的关系表策略合计询问次数落在逐组合下界之和 49 与上界之和 62 之间。共用词元的不同组合可能依赖同一个隐藏义项，两端界不一定能在一份联合解释中同时取到。没有给可接受义项假设概率。金标由词义标注提供，关系由词典推出；本次测量的单位是义项揭示次数，涉及整句理解或人的实际耗时需要另行验证。[语料与标注成本查新](wsd-clarification-prior.md)

在本目录可以重放开头的例子，或对同一词对询问方向。第一行会返回 `right_narrower`，第二行返回 `true`。两条命令的已知输入都只有 group 的一个词义。[查询接口](wordnet_sense_query.py)

```sh
python -I -B wordnet_sense_query.py wordnet-3.0-nltk.zip group team --left-sense 00031264
python -I -B wordnet_sense_query.py wordnet-3.0-nltk.zip group team --left-sense 00031264 --question right_narrower
```

重建命令会核对两份源文件和词典的 Git 对象摘要。新目录中同时生成逐项账本、总表和独立核验记录。另一套实现使用 NLTK、DOM 解析器与候选集合枚举，重建了 367 处位置组合、430 种可接受的局部解释，对照了 8,600 条“问法 × 顺序 × 解释”的询问轨迹。[复现入口](wsd_clarification.py) · [独立核验](wsd_clarification_check.py) · [核验记录](wsd-clarification-checks.json)

```sh
uv run --no-project --python 3.13 --with nltk==3.9.2 -- python -I -B wsd_clarification.py wordnet-3.0-nltk.zip wsd-data fresh-wsd --fetch --check-release
```
