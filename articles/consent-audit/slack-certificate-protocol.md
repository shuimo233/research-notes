# 从完整 CI 时间记录中选择最少的审计证据

本协议在获取作业步骤时间或进行计分前登记。模拟一份旧报表在保管方和审阅方之间共享。保管方拥有全部真实时间，审阅方拥有粗区间和旧类别。保管方可为新版报表选择并披露若干原始时刻。证书要求：任何同时符合旧报表和已公开原始值的完整时间表，都产生相同的新版标签。核验只使用读数的位置与值，证明不依赖选择算法赋予位置编号的隐含信息。

## 来源与样本

使用 [运行清单](slack-certificate-pins.json) 中已冻结的公开 GitHub Actions 运行与尝试。六个仓库各取 2026-11-01 至 2026-11-22 查询窗口内最近的 12 条已完成 push 运行，按 GitHub API 返回顺序冻结。用运行尝试级 jobs 端点分页获取记录。任务只用有至少五步带开始与结束时刻的已完成作业。同一运行按 `SHA-256(仓库 + 换行 + 运行编号 + 换行 + 作业编号)` 升序取前八个合格作业。每份作业按步骤编号取最初至多 24 个带全时间戳的步骤。以这些时间戳中最早所在分钟的起点为零，保留整秒精度。每个步骤端点独立列为一个位置。若真实间隔为负，仍按同一阈值规则计数。冻结来源、处理日志及相对时间，不公开 API 返回的 runner 或机器字段。[GitHub 作业 API](https://docs.github.com/en/rest/actions/workflow-jobs)

## 审计合同

每个位置公开起点对齐的 60 秒宽的闭整数带，并公开三类旧标签。用后时刻减前时刻定义时间差，标签是达到的阈值数。对每步用结束减开始，阈值为 `[0,1,10,60,300]`。对相邻保留步骤用下一步开始减上一步结束，阈值为 `[0,1,10]`。对窗口用最后一步结束减第一步开始，阈值为 `[0,60,600]`。新版报告覆盖同一组关系，三类阈值依次改为 `[1,5,30,120]`、`[-1,0,2,5]`、`[30,120,300,900]`。这些规则模拟监控报表改版，使用真实时间作为回放数据。

## 比较与效用门槛

公布全披露、使用旧报告的最小固定重读、事后逐项保留最少追加证据、对固定方案做反向删除、全局覆盖贪心、最优证书。逐项方案按窗口、步骤耗时、相邻空档的顺序处理，继续利用已经选择的值。每次优先选最少新增值，平局取位置顺序最早的组合，查找至多两个新增值即可。反向删除从最小固定名单开始，按索引降序，每次在仍能证明整个报告时删掉该值。对所有方法记录同一份原始事实下的披露数，任一证书均应对全部相容实况成立。精确搜索用公开的节点上限。达到上限的任务单独计数并给出界。

事前效用条件为至少 200 项不同作业、每条标签可由独立原始约束核验器重算、覆盖贪心比固定名单至少少披露 10% 的时刻、全局精确最优汇总至少比两种使用真值的对照中较好的一个少 3%。还要求精确搜索解决至少 99% 的任务，贪心在精确任务上的总读取数不超过精确最优总数的 5%。若只有界，以保守的界和最差情况判断总量。比较的是示例报告需要的精确时刻数，实际数据传输费用、人员时间与保密强度不由本实验估计。

在小型整数网络上枚举真实世界、披露子集和所有反事实最小支持，比较覆盖式和实际证书。对真实作业用独立最短路或差分可行性检查每份报告及披露证书，核对搜索返回的证书与界。报告覆盖实例的大小、解的最优性和所有排除项目。
