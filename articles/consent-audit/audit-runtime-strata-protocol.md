
# 冻结协议：组内按宽度分层，能否去掉共用一档的尾部代价？

沿用固定 SNLI 分数和三实况分组。Git 对象分别为 09efe9dbdb03c0826bfc884e6cc2228ebbd551b8 和 06cc9ac4fa4c04dff0b840475c5c0a34c3be5595。使用上一轮逐行最小宽度的同一 CPU ONNX 图，摘要 595bfd653973f8065c9e31cac909b5646f5cf4e0c8964c5c8683445b732f08fe。按实际有效宽度分桶调用，同会话四线程。所有计时批次必须逐位符合原档案。

## 调度器

同一共同档位分布应用于全部实况。继续以 1/2 概率独立抽档。余下批次中，合规组保持组间独立。每组按请求索引升序拆成尽量大的二次幂大小的子组。每个子组取 1、2 或 4 个等量档位层，层数为子组大小与 4 中的较小值。按档位顺序切割共同分布的累积概率。每层独立抽一个档，重复给对应份数，再把所有抽到的档位均匀随机排列给子组的请求。

数学核验在所有正条件拒绝率、任意共同档位分布下进行。用独立完整概率表验证非均匀分布、允许换位的配对、单实况活跃及多个实况。计时使用八档等权。每个有限回放的前 8 个批次对全部三种调度复用相同的逐项档位。后 8 批使用逐项、原有组内全共用和新分层。对新调度，在每个子组随机排列请求位置，然后循环置换层号，在每层的 8 除以层数个档位上遍历；批次顺序在子组之间分别随机打乱。三种调度下，每轮每题每档恰好出现两次。

## 计时与验收

原来测过的目录为 0、12、24、34、48、59，新增计时目录为 5、17、23、37、45、53。取全部三个实况和零分差门槛的分组。两个阶段共两轮，种子固定为 7441887。每个目录和实况每轮 16 批，共 1,152 个批次单元、3,456 项计时。三种调度轮换先后顺序，包含数组准备、输入检查、执行和回填，排除模型载入、预热、分词、构造抽签表及核对分数。

主要比较新分层与逐项调度。两轮都必须同时满足 P95 耗时比例至多 0.95、配对中位耗时比例至多 1.05、实际不同宽度种数的均值比例至多 0.95。分开报告新目录和已有目录。新目录每轮 P95 不得高于逐项对照的 1.05 倍，才记为迁移门槛通过。报告与原共用一档调度的比较和全部未通过结果。宽度和与平方和必须逐项配平核验。此实验衡量同一 CPU 会话内的延迟与分桶次数。
