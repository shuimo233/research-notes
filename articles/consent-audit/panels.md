# 哪几份证据值得提前买？一份可以验算的最低价清单

2026-11-23

代理有没有在未经同意时请求写入？上轮的工具可以读完一份日志，再决定查下一份。有些审计要一次订齐所有档案。这时应该买哪几份，怎样向付费的人证明再少花一点就无法保证结论？

我们先查到了直接先例。Douek-Pinkovich、Ben-Gal 和 Raviv 的广义测试集合问题给每个测试标价，要求所选测试能分开属于不同决策类别的任意两份完整答卷。把本实验的完整读数按“没有请求过”和“至少请求过一次”归类，就可以直接采用这个模型。论文还允许要求多个测试给出不同读数。找到这项工作后，我们把问题收窄到一处具体差异：日志可能互为副本，哪几份同源这件事本身也可能需要花钱查。[广义测试集合原文，第 2、3 节](https://www.eng.tau.ac.il/~talraviv/Publications/GTCP_Sep2019.pdf) · [两轮查新与采用记录](panel-precedents.md)

## 先看一张能验算的账单

同一事件的四份日志依次是 `1100`。如果前两份都来自应用记录器，后两份各自独立，那么一个失实的记录器足以解释两个 1。如果后两份同出于授权回调，则一个失实的记录器也足以解释两个 0。上轮用决策树、逻辑回归和三个采集位置实际生成过这两种归档，两个模型的请求行为相反。本轮复用该归档场景及两套按文件字节计的价格。[采集过程与原始读回结果](lineage.md)

| 可买的来源凭据 | 可买的独立行为报告 | 最低价清单 | 为什么不能更便宜 |
| ---: | ---: | --- | --- |
| 64 B | 128 B | 买凭据，64 B | 两种解释都符合现有记录，空清单无法判定。凭据可以区分两种解释，已经达到最便宜单件的价格。 |
| 192 B | 32 B | 买报告，32 B | 同一对解释仍然要求至少买一件。新价格下，独立报告也能区分它们。 |

改价后，程序复用原有约束，只对新清单做一次候选可行性检查就得到最优解。若换了价格，原有约束仍然成立，但可能不足以单独证明新的最低价；工具会继续找反例。若来源图、历史或项目定义改变，则重新建模。这里的字节是给定文件的逻辑读取量，价格没有计入建档和建立可信来源登记的成本。[样例输入](lineage-example.json) · [可逐条复核的 64 B 证书](panel-sample-certificate.json)

在另一个有四项可买证据的构造例里，一次订齐的最优解是买 a 和 d，花 12 个费用单位。如果允许看完一项再选下一项，最优策略的最坏费用是 8。这两个答案对应不同的采购约定，可在下单前用同一份输入算出。[四项报价](lineage-mixed.json) · [按读数改变下一步的策略](lineage.md)

## 哪些可以直接用，哪些需要自己做

最低价清单采用已有的隐式命中集算法。先让求解器给出满足已知必要条件的最便宜清单，再问来源审计器：买完这些，还有没有两个请求行为相反、读数却完全相同的世界？如果有，就把这对世界导出的必要条件交回求解器；如果没有，清单确实够用，同时其价格已达到已知条件给出的下界。代码直接调用 PySAT 的 RC2 和基数编码器。精确搜索需要的时间仍取决于输入规模。[隐式命中集原文](https://doi.org/10.1287/opre.1120.1139) · [RC2 实现](https://pysathq.github.io/docs/html/api/examples/rc2.html) · [本轮工具](panel.py)

本轮作的适配是让**同一个反例给出一条关于独立来源数量的必要条件**。设每种解释从历史到未来始终最多有 f 个失实的采集根。固定两种相反的行为解释及各自的来源图，只看那些在双方诚实时理应给出不同读数的报告。每份报告连一条边，左、右端点分别是它在两种解释下的采集根。同一对端点之间的多份报告可来自副本。历史已经迫使某个根失实，它就已经用掉一份故障额度。若两张图对某项可信同源检查给出不同答案，买它就足以分开这一对。

- **端点一一对应时。** 去掉与历史已迫使失实的根相接的边，合并两端都相同的边。若余下各边互不共享端点，设左、右各还可坏 r₀、r₁ 个根。除了买能区分两图的可信检查，唯一的办法是买到至少 r₀+r₁+1 对不同端点。每多坏一个根至多盖住一对；反过来，至多 r₀+r₁ 对时，可以把要盖的边分给两侧，双方都不超额。独立来源时，这就是已有的纠错多覆盖条件。[抗错识别码的多覆盖归约](https://ieeexplore.ieee.org/document/4608978/)
- **多条边共享端点时。** 固定左世界一组允许失实的根，丢掉它们覆盖的边，再丢掉右侧历史已迫使失实的根所覆盖的边。其余已购报告须涉及多于 r₁ 个不同的右根，或者清单中须有一项能区分两图的可信检查。否则把这些右根也设为可失实，就得到一对能给出相同读数的世界。对每个允许的左侧集合都满足此条件，也就足以分开该对解释，因为任何共同读数都会给出一个违反条件的左侧集合。程序从查到的反例提取一个这样的集合，再交换左右做一次，无需预先列出全部集合。[带两侧预算的点覆盖先例](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.STACS.2016.45) · [独立枚举检验](panel_check.py)

四份日志就是后一情形的反例。如果误把四对不同的端点当成四个独立证人，会以为最多一个坏根时买全四份肯定够。实际上，一个世界的应用根和另一个世界的授权根正好把四条边全部盖住，两者都能交付 `1100`。只有这四份可买时，程序返回两种完整解释，直接证明花光预算也无法判定。[可复现的无解输入](lineage-ambiguous.json)

## 如何核对“最低”

对于每条数量约束，先取每组报告的最低报价，再把所需组数里最便宜的几组相加。若有能区分两图的可信检查，还要与这些检查的最低价取较小值。同一条约束中的报告组互不重叠，所以这是满足该条约束的精确最低价。对全部约束取这些下界的最大值。如果这个数已经等于一份可行清单的价格，读者只要验各项报价和清单的可行性，就能验最低价。若尚有差距，回放器会对全部必要条件一起调用 RC2 求下界。回放核验的是清单、费用和据以算出下界的事实。

| 对照 | 实测结果 |
| --- | --- |
| 291 个小场景，每个枚举所有可买子集和所有相容完整读数 | 普通反例法和来源数量法的最优价及判定均与穷举一致。136 个需要采购且有解，87 个买全仍无解，42 个历史矛盾，26 个仅靠历史即可判定。 |
| 136 个有采购解的场景，回放来源数量法的证书 | 101 个用单条条件的算术下界就够，35 个需要联合求解多条条件。 |
| 四个日志名，左右各选一对合并，各有 6 种选择，再测 3 个同源核验价 | 108 次配对比较中，来源数量法保留的必要条件都更少，最优价相同。该网格也计入上述 291 个场景。 |
| 固定真值与来源图后，逐一枚举采购子集，对照能否产生共同读数 | 定向条件族通过 788 项核对，其中满足匹配条件的 676 项也通过单条匹配条件核对。 |

独立来源对照更容易手算。10 个独立根，每根一份单位价格的报告，最多 2 个根可能失实，需要买 5 份。若只允许在原购买项目上写“这批里面至少买一份”，一条有效条件至多能排除一个大小为 4 的清单，否则它还会排除一份大小为 5 的可行清单。因此排除所有四项清单至少要用 C(10,4)=210 条，普通反例法实际生成了 210 条。一条“至少五个不同根”的数量条件即可表达同样的要求。这个数字衡量交给求解器**编码前**的条件条数，不能换算为运行时间倍数。阈值、组合计数与通用基数编码均有先例。[Sinz 的基数编码](https://www.carstensinz.de/papers/CP-2005.pdf) · [批量结果](panel-results.json)

## 复现

在仓库的 `articles/consent-audit` 目录执行。第一条求最便宜的固定清单。第二条只用标准库验算公开的 64 B 证书。第三条重跑测试，输出可与公开 JSON 对照。

```sh
uv run --no-project --python 3.13 --with python-sat==1.9.dev24 -- python -I -B panel.py lineage-mixed.json
python -I -S -B panel.py lineage-example.json --verify panel-sample-certificate.json
uv run --no-project --python 3.13 --with python-sat==1.9.dev24 -- python -I -B panel_check.py
```

首次输出可保存成 JSON。只改输入中的价格时，用 `--reuse 旧结果.json` 继续；以 `--mode one` 可运行普通反例对照。小样本核对有独立的枚举实现。生产输入还需给出覆盖真实情况的候选来源图、稳定的行为、可信的同源核验，以及可信的故障上限。[试验口径](panel-protocol.md) · [完整核查记录](panel-precedents.md)

给定满足上述假设的审计记录和报价，工具可以交付一份最低价固定清单及其理由，或者交付一对证明全买也不够的解释。查新定位了优化目标、求解循环、纠错阈值和图覆盖的先例。尚待核实的是，这些来源假设和取证菜单的具体组合是否已经有完全对应的实现。

那 35 个需要联合求解的例子也有明确的后续起点。Berg 等在 2023 年已经演示了如何给 MaxSAT 优化过程输出可独立检查的证明。要接到本工具上，还要验证从来源记录、采购条件到求解器输入的转换，并让检查器接受生成的证明。当前公开结果中这 35 个例子仍用 RC2 回放。[Berg 等的原文](https://www.cs.helsinki.fi/u/jezberg/papers/CADE2023_Berg_Bogaerts_Nordstrom_Oertel_Vandesande.pdf) · [VeriPB](https://veripb.org/)
