# GNSS 共享钟差、位置判别和卫星选择的先例

本次检查有界伪距的集合成员定位、卫星故障完整性监测、从原始测量判断道路候选，以及 Android GPS L1 C/A 的可独立核验数据口径。本文比较离线有限候选上的结论。航空 RAIM 或道路导航完整性评估还要求相应的误导概率、告警限、连续性与时间口径。

## 最接近的原始工作

- Drevelle 与 Bonnifait 用有界卫星位置、伪距和高程数据求用户位置与公共钟差的联合可行域。允许一条坏测量时，用 \(q\)-放松的集合求逆围住所有满足至少 \(m-1\) 条测量的状态。后续研究用相同的区间分析处理无线电导航多径，或与三维道路图联合约束短程轨迹，并公开了实测回放。因此，公共钟差、有界测量、剔除任意一条坏源以及道路范围内的可信位置集合都已有直接先例。 [A Set-Membership Approach for High Integrity Height-Aided Satellite Positioning](https://www.hds.utc.fr/~bonnif/pdf/2011_GPS_solution.pdf) · [Interval-Based Fast Fault Detection and Identification Applied to Radio-Navigation Multipath](https://hal.inria.fr/hal-01258946/file/IJACSP-2015%20author%20version.pdf) · [Localization Confidence Domains via Set Inversion on Short-Term Trajectory](https://www.hds.utc.fr/~bonnif/pdf/2013_TRO_short_term_trajectory.pdf)
- Fouque 与 Bonnifait 已直接从原始 GPS 伪距和多普勒在候选道路之间匹配，无需先计算通常的全球位置。方法用概率状态与粒子滤波维护多个道路假设。Su 的区间监测论文第 5.2 节合并多个故障模式下的可行解集，再从误差包络、故障概率及未监测概率生成保护水平。相比之下，本实验冻结有标签的有限位置和一个允许坏星的误差合同，并从跨标签输出的首次重合导出确定性模型边界。 [Matching Raw GPS Measurements on a Navigable Map Without Computing a Global Position](https://www.hds.utc.fr/~bonnif/pdf/2012_T-ITS.pdf) · [Towards Interval-Based Autonomous Integrity Monitoring，第 5 章](https://doi.org/10.15488/19619)
- Blanch 等人用完整性支持消息建模标称误差和故障概率，计算应监测的故障子集及保护水平。Luo 等人用信号质量、几何与完整性支持消息进行卫星选择，并用真实的 MGEX 站点观测评估。还应区分降低接收机实际处理的卫星数量，与合并故障模式从而减少子集解算次数。两类减少方案均已有先例，卫星较少不能单独建立原创性。 [Advanced RAIM User Algorithm Description](https://www.ion.org/publications/abstract.cfm?articleID=10462) · [Satellite Selection Methods for Multi-Constellation Advanced RAIM](https://doi.org/10.1016/j.asr.2019.12.015) · [Baseline ARAIM 算法更新](https://web.stanford.edu/group/scpnt/gpslab/pubs/papers/blanch_ION_ITM_2022_ARAIM.pdf)

## Android 码伪距与广播星历的可核验口径

1. **原始 GPS 时间。** Android 的 `GnssClock` 时间从 `TimeNanos` 减去 `FullBiasNanos` 与 `BiasNanos` 得到 GPS 时间估计。每条测量的 `TimeOffsetNanos` 按当前 API 定义加到本地 `TimeNanos`。按 GPS 周将 `ReceivedSvTimeNanos` 的周内发射时间与接收时刻对齐，再乘光速取得码伪距。GPS 周内时间、GPS 绝对周和日志的 UTC 毫秒不是可互换的坐标。保留整数纳秒直至减去大数和整周，避免绝对时间先转双精度引起精度损失。按接收时刻和硬件钟不连续计数分组，代码锁与已知或已解码的周内时刻同时有效才接收。冻结 GPS 星座、L1 载频及 C/A 码型的识别条件。Google 的较早 MATLAB 脚本会在同一连续片段用首个 `FullBiasNanos`，而且第 90 行对 `TimeOffsetNanos` 使用减法，与早期 Google 解析白皮书及 Android API 的加法约定不同。跨工具核对要固定代码版本、源日志约定和非零偏移处理。 [Android GnssClock](https://developer.android.com/reference/android/location/GnssClock) · [Android GnssMeasurement](https://developer.android.com/reference/android/location/GnssMeasurement#getTimeOffsetNanos()) · [Android GnssLogger 有效观测定义](https://developer.android.com/develop/sensors-and-location/sensors/gnss-analyze-raw) · [Google ProcessGnssMeas.m](https://github.com/google/gps-measurement-tools/blob/master/opensource/ProcessGnssMeas.m#L60-L105) · [Google 时间换算白皮书](https://developer.android.google.cn/develop/sensors-and-location/sensors/gnss/downloads/gnss_analysis_tools_from_google.pdf) · [Android 观测生成方法实测对照，式 (2)](https://doi.org/10.3390/s23020777)
2. **L1 C/A 的星历和卫星钟。** IS-GPS-200N 的表 20-IV 给出使用发射时刻计算 WGS-84 地固坐标的方法。钟差多项式用 \(t_{\rm oc}\)，轨道演算用 \(t_{\rm oe}\)。需处理周交界，并使用同一颗星、健康且覆盖相关时刻的星历记录。广播钟差补上轨道偏心相对论项后，L1 C/A 的时钟修正为该钟差减 \(T_{\rm GD}\)。必须确认库返回的钟差是否已包括相对论项或码偏差。RTKLIB `eph2pos` 的钟差包括相对论项而无 \(T_{\rm GD}\)，其 `prange` 在 GPS L1 端减去 \(cT_{\rm GD}\)。GNSSTk 的 `OrbitDataKepler::getXvt` 分别保存 `clkbias` 和 `relcorr`。在固定相同 GPS 周、发射时刻、同条广播星历及健康约束后，用两套实现逐星核对坐标和钟差，比仅比较最后一条定位轨迹更容易发现符号、时间单位及周界错误。 [官方 IS-GPS-200N 文档目录](https://www.gps.gov/interface-control-documents-icds-interface-specifications-iss) · [RTKLIB 星历](https://github.com/tomojitakasu/RTKLIB/blob/v2.4.3-b34/src/ephemeris.c#L183-L285) · [RTKLIB 码偏差](https://github.com/tomojitakasu/RTKLIB/blob/v2.4.3-b34/src/pntpos.c#L136-L144) · [GNSSTk 钟差分量](https://github.com/SGL-UT/gnsstk/blob/stable/core/lib/NewNav/OrbitDataKepler.cpp#L212-L215)
3. **传播与地固坐标。** RTKLIB 单点定位先用伪距和广播卫星钟求信号发射时间。在距离预测中加入地球自转的一阶 Sagnac 项，或等价旋转广播星坐标至接收时刻的地固系，二者只使用一次。含共享接收钟差的 GPS L1 预测可记作 \(P^{\rm raw}=\rho+b-c(\Delta t_{\rm sv}-T_{\rm GD})+I+T+\epsilon\)。其中 \(I,T\) 是单频电离层与对流层延迟，可固定公开的转换模型及选择策略，与不同估计器一并报告。启用或停用修正都会改变残差分布。若评估遵循固定的逐历元卫星状态与修正表，分离半径是该表对应的条件判据。GNSS-SDR 的 PVT 实现嵌入 RTKLIB，所以适合核对观测流程和配置口径。若希望另有独立轨道实现，使用 GNSSTk，而非把 GNSS-SDR PVT 和 RTKLIB 当作完全独立核心。 [RTKLIB 卫星状态计算](https://github.com/tomojitakasu/RTKLIB/blob/v2.4.3-b34/src/ephemeris.c#L738-L806) · [RTKLIB 距离和 Sagnac](https://github.com/tomojitakasu/RTKLIB/blob/v2.4.3-b34/src/rtkcmn.c#L3528-L3538) · [RTKLIB 观测残差](https://github.com/tomojitakasu/RTKLIB/blob/v2.4.3-b34/src/pntpos.c#L275-L305) · [GNSS-SDR PVT](https://gnss-sdr.org/docs/sp-blocks/pvt/)
4. **对照测量表和选择的时点。** Google Smartphone Decimeter Challenge 的数据说明区分 Android 原始字段、组织方广播星历派生量和参考轨迹。逐星核对如使用派生表，必须检查其星历时刻、码偏差及地球自转的定义，避免重复修正。按固定时刻几何选择卫星与先读齐所有码伪距、随后剔除读数是不同成本口径。离线记录可对照逻辑使用量，不能直接推导射频获取开销、导航连续性或节能效果。 [Google Smartphone Decimeter Challenge 数据说明](https://www.kaggle.com/competitions/smartphone-decimeter-2023/data)

## 位置对的精确重合半径

设 \(g_i(x)\) 是统一修正口径下的名义伪距，候选位置 \(x\) 的正常读数有一个对所有 GPS L1 码共用的接收钟差 \(b_x\)，单位为米。对两个不同标签 \(x\) 与 \(x'\)，写 \(d_i=g_i(x')-g_i(x)\)。同一坐标可同时作为两者的正常读数，当且仅当 \(\left|b_x-b_{x'}-d_i\right|\le 2r\)，其中 \(r\) 是每个正常读数的对称误差上限。允许两个世界各有一颗任意坏星时，可在这项比较里先删最多两颗互不相同的源，每颗归给一边；其他源要以同一个钟差之差满足所有闭区间。空交与交集均可用有限删源枚举复核。

钟差之差无限制且剩下至少一个源时，对固定留下的集合 \(J\)，它第一次允许共同回复的半径为 \((\max_{i\in J} d_i-\min_{i\in J} d_i)/4\)。两端的中点给出钟差之差，残差相距不超过 \(2r\) 的坐标可逐个构造相同读数。若允许的钟差之差有界，用中点投影到可行区间再计算最远距离的一半。最后对所有合规删源和跨标签位置对取最小值。与伪距真位置的单世界需求不同，后者只可删一个坏源，等宽情况下残差跨度除以二。该推导为固定名义伪距表的组合判据，广播星历、共同钟差及抗坏测量规则本身属于前述已知方法。

连续地理区域中，若两标签在共同边界两侧可任意接近，连续的名义伪距使所有跨标签位置对的最小重合半径下确界为零。离散候选或事先定义的拒答缓冲区因此是严格正分离半径的组成条件。只有在候选目录确实涵盖参考位置、且误差属于合同的情况下，唯一标签才表示该任务内可证的正确结论。

截至这轮查新，未在核对的 GNSS 原始文献中找到把每个固定卫星组合的首次跨标签共同伪距半径与独立档案中真位置的容限需求分位严格比较，再按预算选择组合的完整等价方案。文献已覆盖其最关键的技术构件。这个结论仅划定本轮比较范围，实测差异、完整性风险和全球优先权要分别检验。
