# 468 条评论可以有两种解释，模型排名还站得住吗？

在 GoEmotions 的 5,427 条测试评论中，有 468 条在两种有依据的标签定义之间发生变化。我们冻结了同一个 RoBERTa 分类器的全精度和 INT8 公开部署，在两套参考上使用完全相同的预测。两者的分数都下降了，**INT8 在两套参考上都领先；即便允许逐条选择如何归类，INT8 的 micro-F1 仍领先 0.2710 至 0.4502 个百分点。** 这两个界都能由实际评论 ID 的一个子集达到。[冻结前公开的比较规则](https://github.com/shuimo233/research-notes/blob/4bf3061c46fa17663ff696e132e3fee61d124ef7/articles/consent-audit/go-model-protocol.md) · [精确分数与见证 ID](go-model-results.json)

随后改变部署做了对照。在相同的 28 个官方细类上，逐条推理时全精度的 macro-F1 略高；相邻八条一起推理时，INT8 反超。七个粗类的排名在两种部署中都稳定。文章末尾给出这次实测翻转涉及的逐条变化以及复核方法。[部署复核结果](go-layout-results.json)

## 两种参考如何改变分数

第一种参考按原发布细标签归入上位类别。第二种先在每位标注者的打分单内部归类，再逐类要求至少两个人支持。两人可以各自用了不同的细标签。先前的逐人对账表明，同一批测试 ID 由此多出 486 个“评论—类别”正例，原有的 5,894 个都被保留。54,263 份官方训练、开发和测试细标签也都能从原始打分逐项复原。[数据审计与第三方发布文件](goemotions.md) · [GoEmotions 原研究](https://aclanthology.org/2020.acl-main.372/)

本轮只改变评测参照。下表包括三个事先指定的输出规则。前两行将概率达 0.5 的细类映射成粗类，允许整条为空；第三行使用同一全精度模型的第一选择。评分在六种情绪大类加 neutral 上进行。Micro-F1 将所有“评论—类别”的命中、漏报和误报合起来计分。完全匹配则要求一条评论的整个预测集合与参考相同。[权重发布者的模型卡](https://huggingface.co/SamLowe/roberta-base-go_emotions-onnx) · [逐条预测与两列参考](go-model-batch.tsv)

| 固定输出 | 预测为正的总数 | 命中新增 486 项中的几项 | 发布细类映射的 micro-F1 | 两人支持粗类的 micro-F1 | 完全匹配条数变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全精度，阈值 0.5 | 4,587 | 96 | 0.66482 | 0.65287 | 3,117 → 2,927 |
| INT8，阈值 0.5 | 4,639 | 95 | 0.66857 | 0.65632 | 3,143 → 2,949 |
| 全精度，仅第一选择 | 5,427 | 129 | 0.68757 | 0.68112 | 3,513 → 3,266 |

以全精度阈值输出为例，原先命中 3,484 项，换参考后命中 3,580 项。micro-F1 的分子是命中数的两倍，而分母中的参考正例增加了 486 项，所以两个得分分别为 6,968/10,481 和 7,160/10,967。预测本身没有变化。INT8 的旧、新命中数分别是 3,521 和 3,616。两档阈值输出有 369 条评论的粗类预测不同；这里考察的是同一训练模型的两种部署行为。第三行是预先规定的输出规则对照，三行结果只覆盖这批固定测试评论。[整数计数及各类命中](go-model-results.json)

## 不依赖搜索也能验算的排名证明

把 486 个新增标签按两个部署是否命中分组，双方均命中 91 个，仅全精度命中 5 个，仅 INT8 命中 4 个，双方均未命中 386 个。按原参考，INT8 比全精度多命中 37 项。无论保留哪些新增项，只有那 5 个全精度独有的命中可能缩小这个差，所以 **INT8 总是至少多命中 32 项**。同时 INT8 总共比全精度多预测 52 项，多命中也必须足以抵消分母增大。[两套输出在新增标签上的联合计数](go-model-results.json)

设全精度命中 T 项，当前参考正例数为 G，INT8 多命中 D 项。由 F1 的定义，INT8 得分更高当且仅当 D × (4,587 + G) > 52 × T。已知 G ≥ 5,894、T ≤ 3,580、D ≥ 32，因此左侧至少为 335,392，右侧至多为 186,160。这个短证明显式覆盖了所有允许的参考选择。它甚至容许逐个挑选新增标签；若只需要决定两个阈值部署谁领先，到这里就够了。

## 精确的领先幅度要尊重整条评论

如果评测方规定全库统一采用一套语义，只需比较表中两个端点。这里再问一个更保守的问题。如果逐条复核时，每条受影响评论可在两套完整标签中选一套，最多可能把分差推到哪里？451 条只增一个标签，16 条各增两个，1 条增三个。有些拆分会给一条评论拼出两套定义都没有给出的标签集。允许每条独立选择也只是一项敏感性假设，没有把这些混合解释视为真实人类情绪。

| 比较，以表内前者减后者 | 所有整条选择下，micro-F1 分差的可达范围（百分点） | 两个端点之间是否可能隐含逆序 |
| --- | ---: | --- |
| 全精度阈值 减 INT8 阈值 | −0.450246 至 −0.270983 | 无 |
| 全精度阈值 减 全精度第一选择 | −3.018255 至 −2.080822 | 无 |

上下界旁都给出一份可回放的 ID 清单。例如只切换 `ed70d2p`、`ee2bd7a`、`ef0droi`、`ef15dzw` 这四条就达到第一行的最小值。它们组成一份达到下界的见证。若放开整条约束，第一组上界只扩大约 0.000035 个百分点，两组的胜负都不变。这份语料支持在两种解释下比较部署；它没有提供用整条耦合才能挽救真实排名的实例。[完整边界与四份见证](go-model-results.json)

整条约束在其他输入上确实可能决定结论。举一个可以心算的两条样例。两条原参考均为 {A}，第一条可整体改为 {A,B,C}。系统甲依次预测 {B}、{A}，乙预测 {C}、{A,B}。完整切换前后的甲减乙分差分别为 1/10、2/21，均为正。若错误地允许第一条只加入 C，则甲减乙变成 −4/15，报告一个不可能发生的翻转。[可直接运行的小例](go-model-linked-example.jsonl)

## 求界的办法和独立核对

固定两套预测 A、B。令 P_A、P_B 是预测正例总数，T_A、T_B 为在旧参考下的命中数，G 是原参考正例数。一条评论 i 整体切换会增加 wᵢ 个参考标签，分别使两套预测多命中 aᵢ、bᵢ 项。选定一批评论、合计新增 k 个标签时，两项 F1 的分母分别固定为 d_A=P_A+G+k 和 d_B=P_B+G+k。将分差乘以 d_A d_B/2，便得到常数 d_B T_A−d_A T_B，加上每条选中评论的收益 d_B aᵢ−d_A bᵢ。两侧均空时使用 F1=0 的约定。

于是对于每个 k，可以把所有 wᵢ=1 的评论按收益排序，取指定长度的最小或最大前缀。其余评论按“已增加的标签数、已切换的评论数”做 0/1 动态规划，分别保留最小和最大收益。每条评论只有选或不选两种动作，完全覆盖其合法状态；同一状态下后续的收益与之前的选择路径无关。用单标签前缀补齐剩余容量后，枚举各 k 并还原分母，得到精确分差端点，也能求从原排名出发实现严格逆序至少要切换几条评论。计算使用有理数，各界都回放实际选中的记录。在两个端点之间，并非每个实数都一定可达。[通用求界和见证程序](go_model_bounds.py)

另一套核验程序不使用这个动态规划，在真实测试集上枚举每种新增标签数所选的评论数量，对每个计数组合在同大小组内独立排序求界，直接把极值见证代入整张测试表重算。它另对 144 个小批次的全部 9,180 种参考选择直接求分，覆盖了 36 个确有严格翻转的批次。真实数据的六套端点计分、四组上下界比较和四份极值见证均通过。[独立核验程序](go_model_check.py) · [核验结果](go-model-checks.json)

## 查新与归属

判断聚合文献已讨论先合并理由和先投票的区别。SHALA-LLM 已逐人映射 GoEmotions 粗类并训练软标签分布。Kulshreshtha 等已实测同一输出换人工参照的得分变化，Fernández-Barrios 等已推导固定二分类输出在共享未知参考下的 F1 排名精确界。本研究采用固定参考正例数后将 F1 差化为加性对比的做法，并为整条评论的联动选择计数、回放见证。受约束的动态规划也是已有算法技术。本次可以归属的实证结果是指定的两份公开模型文件、两套可从真实评审重建的语义、上述数值和排名保证。查新覆盖的公开材料未发现这组同一部署、同一批次的对账；全球优先权、一般模型性能和其他平台上的领先均未建立。[先例笔记](goemotions-model-prior.md) · [SHALA-LLM 附录 B.3](https://arxiv.org/html/2606.05376v1#A2.SS3) · [人工参考变化研究](https://arxiv.org/abs/2610.03825) · [已发表预印本中的 F1 排名界](https://arxiv.org/abs/2611.01712)

## 直接使用与完整复现

只复核数字时，使用 Python 标准库即可。在本目录运行前两条命令可重建结果和验证见证。第三条演示把自己的两套分类输出接入审计器的格式，每行写一个样例 ID、原参考、可替代参考及两套预测，标签名可以自定义。替代参考须保留原参考中的所有标签；两套预测都允许为空。工具输出从原排名到严格翻转所需的最少切换数和一份具体见证，若不能翻转则为 null。原排名本来并列时也用 null，此时可看分差上下界。动态规划适合本例这种多数评论仅增一个标签的情形；大量长标签组会增加计算费用。

## 补充实测：同一权重换成八条一批，哪些结论还能重用？

主结果发布后，我们核对了模型卡使用的 28 个细类。单例全精度 macro-F1 为 0.449909，三位小数与发布者报告的 0.450 一致；单例 INT8 为 0.448501，发布者报告的是 0.447。因而不能把逐条决策当作权重文件自身的唯一结果。我们另行公开复核约定后才运行第二种部署。它按官方测试集的原有顺序将相邻八条一起送入模型，每批右补齐到最长一条，最后一批保留实际条数。权重、CPU、软件版本、阈值和原始 5,427 条文本均与前面相同。[补充实验的事前约定](https://github.com/shuimo233/research-notes/blob/14285d9bec0349b9fe8b8af954b3ba4aa83fb0a5/articles/consent-audit/go-layout-protocol.md) · [模型卡和补齐示例](https://huggingface.co/SamLowe/roberta-base-go_emotions-onnx)

| 推理和评分条件 | 全精度 | INT8 | 得分较高者 |
| --- | ---: | ---: | --- |
| 单例，原发布 28 细类 macro-F1 | 0.449909 | 0.448501 | 全精度 |
| 八条一批，同一 28 细类 macro-F1 | 0.449909 | 0.452153 | INT8 |
| 单例，原发布细类映射后的 7 粗类 micro-F1 | 0.664822 | 0.668565 | INT8 |
| 八条一批，同一 7 粗类 micro-F1 | 0.664822 | 0.670402 | INT8 |
| 单例，先在每人内部归类后的 7 粗类 micro-F1 | 0.652868 | 0.656321 | INT8 |
| 八条一批，同一逐人归类的 7 粗类 micro-F1 | 0.652868 | 0.659345 | INT8 |

前两行是一次真实的排序翻转：评测细标签、指标和阈值均未更改。全精度模型在两种部署下对全部评论给出相同的二值细类集合；INT8 有 **465 条评论**的细类集合改变，映到粗类后仍有 **417 条**的集合不同。细类 macro-F1 先为每类计算 F1，再对 28 类等权平均；粗类 micro-F1 则跨七类汇总计数，两种指标内各自都进行了同口径比较。本次同时改变组批与补齐，基于运行记录可以归因到这套部署变更。批内其他文本、补齐位置和具体数值算子各自贡献多少，尚未从这个比较中识别。ONNX Runtime 的文档说明动态量化会在运行时计算激活的量化参数，这只提供了一个可进一步检验的机制。[部署差异文件](go-layout-changes.tsv) · [全表计分与运行结果](go-layout-results.json) · [ONNX Runtime 量化说明](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)

在八条一批的预测上再次允许 468 条评论各自选用一种完整参考，INT8 的粗类 micro-F1 仍比全精度高 **0.484464 至 0.728533 个百分点**。看到这一结果后，又补问了一个要求两种部署对同一评论使用同一份参考的问题：单看 INT8，八条一批比逐条推理究竟多得几分？让两个布局共享每条评论的选择并重新求界，实际可达到的改善为 **0.084635 至 0.411037 个百分点**。该比较是事后分析；两端的 ID 清单可回放。这个有限测试集上的改善并不估计新数据上的优势。[两组精确界与见证](go-layout-results.json) · [独立枚举核验](go_layout_check.py)

要把这项结论用于部署，至少要固定预测文件对应的推理设置、指标以及参考标签含义。仅知道 checkpoint 名称，无法决定本例中 28 细类 macro-F1 的赢家。仅问“468 条评论有多种解释”，也无法推断 7 粗类排名会翻转。上述表格给了两种问题各自可查的答案。
