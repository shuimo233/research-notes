# 32 个故障原因，怎样让接收方查得动一份保证？

2026-11-22 · Stateful Identification 0.5.0

假设一个占用中的分片用六位偶校验地址标识。监控按位重复采样，报告每一位读到 1 的次数；不同故障原因可以有不同的错读额度。要向某个保证可用的分片写入，规划器须排除“有一份读数能同时解释全部停机位置”的可能。这里给出一个可以从 32 个原因中删去任意一个就改变结论的实例。上一轮的三变量归约无法保持这个实例每个子集的答案。

新版在通用计数搜索之前，尝试从原始规则的和中推出每个读数的范围。它还能把得到范围所用的行号随声明交付，接收方可以用自己的预测表重算。对于只需知道能否安全行动的调用者，可以明确请求只核验行动保证；要求证据中每一行都不可删的调用者仍可选择逐行核验。[框架接口](../../packages/stateful-identification/README.md) · [预先确定的检验及后续修订](PROTOCOL.md)

## 四行的用途及复杂度

设第 $j$ 位读 $n_j$ 次，其中有 $z_j$ 个 1。行 $s$ 的错配为 $D_s(z)=\sum_j |z_j-n_js_j|$，其额度为 $r_s$。在整数盒内，这就是符号系数不等式 $a_s z\le b_s$，其中 $a_{sj}=1-2s_j$，$b_s=r_s-\sum_j n_js_j$。

若两行除第 $j$ 位以外全都相反，其他位置在两行上的总错配固定为 $\sum_{k\ne j}n_k$。因此两行额度之和直接约束 $z_j$ 或 $n_j-z_j$。这种共享位置界已有明确先例。偶校验六位地址的两行不可能恰好有五位不同，所以在这张表上，两行直接推不出任何单坐标界。[Hufsky 等，2011，引理 2](https://doi.org/10.1186/1471-2105-12-106)

四行却可以。固定一个目标位，将其余五位分成大小为 1、1、3 的三组。在各组上复制三位偶校验的四种签名；这三个组大小均为奇数，四行都在同一校验侧，每个干扰位各有两个 0 和两个 1。必要时翻转一组以匹配目标位的奇偶。将四条不等式相加，干扰位全部抵消，目标位留下系数 $+4$ 或 $-4$。

**精确范围。** 一次使用最多四条原行、取非负实线性组合、消去所有干扰位，最后才对整数取整。暂不使用盒边界作为组合项。对于原线性系统实可行的情形，两行及等权四行足以取得这类推导可达的最强上下界，最后再与原盒相交。若允许多轮切割、更多原行或让盒约束参与消元，可能得到更强的界。依据是消去干扰列的非负权锥的极射线：至多四个非零权的最小正依赖，除一列退化情形外，只需两项等权或四项等权。与相反方向的射线混合无法改善同向最优端点，因为实可行点必须同时满足两侧约束。分类及正锥分解已有原文。本次未将其列为新定理。[Arratia 与 DeSalvo，定理 3、命题 3–4](https://arxiv.org/abs/1105.2834) · [推导、原文对照与检索边界](precedents.md)

实现把两行法向之和编码成两个位掩码，分别标出系数 $+2$ 和 $-2$ 的坐标。对相同掩码键只留最紧右端和产生它的两个原始行号。枚举目标坐标和第一对行，在哈希表中找其余坐标恰好相反的第二对；第二对在目标位只有三种取值。因此 $h$ 行、$m$ 个活跃坐标最多需要 $O(mh^2)$ 次字典查询，表中至多 $O(h^2)$ 个键。长掩码的算术和哈希成本、整数位长、后续残余求解和极小性检查均另计。这个计数界针对单个行组的一次编译。

取得 $L_j\le z_j\le U_j$ 后，令 $y_j=z_j-L_j$，仅保留 $U_j-L_j$ 次。每条零预测行扣除 $L_j$，每条一预测行扣除 $n_j-U_j$。这是原问题与残余问题可行**计数记录**之间的一一对应。删去某一行后，由它参与导出的界可能失效。发布实现对删行子问题重新求界，独立检查器也只使用来源行均在当前子集内的求和建议。[范围编译](../../packages/stateful-identification/stateful_id/_bounds.py) · [独立检查器](../../packages/stateful-identification/stateful_id/audit.py)

## 为什么 32 行真的缺一不可

取六位的全部 32 个偶校验向量 $s$，每位任取正整数重复数 $n_j$，再任选 $0\le u_j<n_j$。单位盒中离中心行 $s$ 最远的顶点是 $w_s=u+\mathbf1-s$。给这行设额度 $r_s=D_s(w_s)-2$。其余偶校验行与 $s$ 至少相差两位，因此 $w_s$ 满足其余每条行，单独不满足 $s$。放宽 $s$ 两次也可直接用这份记录。

整体无解还需排除单位盒外部。对每个整数 $z_j$，令 $q_j$ 为它离 $[u_j,u_j+1]$ 的距离，并选出使该坐标离对应行最远的一侧 $f_j$，即 $z_j\ge u_j+1$ 时取 0，否则取 1。记 $Q=\sum q_j$。全符号行 $f$ 的 $D_f(z)-D_f(w_f)$ 为 $Q$。若 $f$ 为奇校验，翻转 $q_j$ 最小的一位，得到一条偶行，其差为 $Q-1-2\min q_j\ge-1$。在两种情形中都有一条偶行超出额度。故 32 行全体无解，任一真子集有解。

如果希望用每行对应一个凸约束、同一组共享整数变量、保持**所有子集**的可行性，三维整数 Helly 定理给出空交必有至多八个约束作证，四维上限也只有 16。因此此例至少需要五个这样的整数变量。特定任务仍可有其他低成本算法。特别是上述已知形状可以从完整输入的仿射行预算中恢复 $u$，直接返回全部 32 个行号；我们的计时包括这个专用对照。四位完整地址的 16 行同理，取 $r_s=D_s(w_s)-1$ 即可。[整数 Helly 定理](https://doi.org/10.1007/BF01949705) · [专用对照实现](compare.py)

## 正确性与使用边界

在原六位偶校验实例上，每种探针约采样一百万次。独立检查器在 4,000 个搜索节点限额下接收 48 个求和提示，用 632 个节点验证了 32 行证据及逐行删除后的可行性。使用完全相同的表和证据、移除提示，检查器在 4,000 个节点处返回未判定。提示给出的是原始行号，所有系数和右端均由接收方重新计算。在四位完整地址的对照上，有无提示均需 101 个节点，可见提示并非每个输入都能获益。[原始输出](evidence.json)

小规模独立枚举在 211 张表的 16,543 个计数向量上逐点比较原问题与残余问题；另有 9 次抽样生成了完全相同的列，未纳入这项内部列表示试验。对另外 32 张实可行表，独立的有理数消元程序共枚举 8,481 个原行支撑集，所得最强单坐标界全部一致，其中 14 张表从四行得到严格强于两行的界。[枚举与实测](experiment.py) · [有理数验证](rational_check.py)

在文件系统里建立 16 个独立 SQLite 分片，轮流持有一个真实写锁，逐库验证竞争状态，再向汇总读数注入模型允许的错误。小清单四类探针分别读取 1、2、3、1 次。穷举允许的全部计数组合后，596 次推荐写入全部提交，由新连接逐库读回，且没有写入被锁分片。这里按计数记录计数，重排相同探针内回答的先后不会重复记一次。锁在采集与写入间保持不变。这项实验验证行动正确性，未测量线上故障率或采样节省。[SQLite 事务语义](https://www.sqlite.org/lang_transaction.html)

本轮可报告的候选增量是将符号行的既有分类编译为支持异质预算的索引，并用原行来源在接收端复算计数界。四面体例、两行偏离界、至多四项的权重分类、哈希折半配对和整数 Helly 界均有直接先例。本轮未找到与整个接口及编译器完全相同的发表记录，检索无法确立全球优先权。[逐项查新](precedents.md)

在本目录运行 `python -I -B experiment.py` 和 `python -I -B rational_check.py`，均只依赖标准库。性能脚本使用 SciPy、NumPy、Git 和含基线提交 621f118 的仓库历史，运行 `python -B compare.py`。安装和核验器用法见包说明。[框架安装与接口](../../packages/stateful-identification/README.md)
