# 多等一轮反馈，能省多少复查字节？

这次把上一轮的三批探索放到事先固定的 10 组 npm 发布档案上。允许一次错读时，三批比任意两批的精确最优少预订 **3.72%** 字节。5 个包严格节省，5 个持平。预设门槛要求至少 7 个包节省，且合计至少节省 5%，因此未通过。三批总预算仅比逐问最优高 **0.60%**。 [冻结预案](weighted-rounds-protocol.md) · [逐案输出](weighted-rounds-results.json)

## 怎样在给定反馈次数下定价

沿用[异价两批](weighted-batches.md)的诊断合同。旧解释只能在一项测试上与新增解释不同，且没有剩余错读额度。新增解释还容许 $f$ 个单次翻转。这里固定所有初次测试按价格从高到低进行，把前缀切成连续批。某批唯一一项与新增解释不符时，下一批仅复查该项，共 $f$ 次。所有已读回复都与新增解释相符时，最后一批对剩余项目各复查 $f+1$ 次。回调拿到整份报价清单，批内没有反馈。

记降序价格为 $c_i$，累计价为 $P_j$，总价为 $T$。常规批从 $i$ 到 $j$，若该批收到第一处不符，最坏总成本是 $P_j+fc_i$。原因是批内最贵的测试也可能是不符项，且为了排除仍有余量的新增解释必须追加 $f$ 个同向读数。若前 $j$ 项都已问过且均相符，固定尾批的最坏总价是 $P_j+(f+1)(T-P_j)$。尾批对每个未问项目都必须安排 $f+1$ 次，否则至少一个旧解释的诚实回复仍可被新增解释的错读模拟。任意时刻保留全部相容解释，超出故障合同的回复可以返回不一致。

给一个报价上限 $C$ 后，在第 $i$ 项可尽量装入至满足 $P_j+fc_i\le C$ 的最远 $j$。起点向右移动时，原来的可行后续计划可删掉已问项，保留绝对累计价相同的批末。删掉的前段只会降低该批最大单价，尾批总价也只降不升。因此每批取最远终点不会失去可行解。用前缀和二分找每批终点，再在整数上限上二分，可得到**固定降价顺序下的精确最小上限**。这是有序切分的结论。两批允许任意组合时已出现较优清单，多批的任意排序最优值仍未给出。 [调度与执行接口](weighted_rounds.py)

### 与逐问最优的预算差

若可用 $r$ 批，记逐问最优 $A=\max_i(P_i+fc_i)$。本方案的费用至多
$$
A\left(1+\frac{f}{1+(f+1)(r-1)}\right).
$$
$f=0$ 时一次查询即可买齐所有项目，费用为 $T$。对于 $f\ge1$ 且 $r=1$，上式由 $(f+1)T\le(f+1)A$ 得出。对 $r\ge2$，记 $\varepsilon=A-T$，取 $C=A+\delta$，其中 $\delta=fA/[1+(f+1)(r-1)]$。每个项目至少可单独加入当前批，因为 $C\ge A$。若起价为 $q$ 的批结束在 $j$，且下一项价格为 $q'$，有
$$
P_{j+1}+fq>C,\qquad P_{j+1}+fq'\le A.
$$
所以 $q'<q-\delta/f$，且尾部余价 $T-P_j<(f+1)(q-\delta/f)-\varepsilon$。如果经过 $r-1$ 个普通批仍有尾部，起价每次下降至少 $\delta/f$，而 $c_1\le A/(f+1)$。于是尾批总价
$$
T+f(T-P_j)< A+fA-(r-1)(f+1)\delta-(f+1)\varepsilon\le C.
$$
若任何一批装完全部项目，则无需全相符路径上的尾批。提前收到分歧仍有一批复核名额。这个界在两批时与已证明的降序前缀紧界相同。 [先例审查](weighted-rounds-prior.md)

**一次错读、三批的紧上确界是 $13/11$。** 第一批价格至少为首项 $q_1$。若下一批起价为 $q_2$，逐问界还给出 $q_1+2q_2\le A$。与 $q_2<q_1-\delta$ 合并得 $3q_2<A-\delta$。第二批之后若仍有待问项，尾部价格 $S<2(q_2-\delta)-\varepsilon<2(A-4\delta)/3-\varepsilon$。因此取 $\delta=2A/11$ 已可支付 $T+S$。

为验证紧性，取整数 $k\ge2$，四个价格为 $5k,3k,k,k$，再加 $k-1$ 个单位价。此时 $A=11k$，$T=11k-1$。以低于 $13k$ 但不低于 $12k$ 的上限执行，第一批只能到 $5k$，第二批只能到第一个 $k$。尾部剩余 $2k-1$，所以精确三批成本是 $13k-2$。这个值落在上述区间，更低的上限由可行性单调排除。该族逼近 $13/11$。此紧界只覆盖一次错读的降序连续三批。例如取 $k=6$，有序最优为 76，允许第二批越过一个价 6 的项目并改问价 1 的两项，就能把最坏成本压到 74。

## 独立档案结果

每个候选只把一个同路径 JavaScript 文件换成真实旧版内容。正式档案的数据来自官方发行，单次答复翻转由程序注入。每次查询实际把对应文件字节交给 SHA-256 核验器。预订价取新旧两版中的较大未压缩字节数。试验没有观测线上延迟、磁盘负载或真实事故率。 [npm 完整性元数据](https://github.com/npm/registry/blob/main/docs/responses/package-metadata.md)

| 方案 | 一次错读，合计最坏预订字节 | 两次错读，合计最坏预订字节 |
| --- | ---: | ---: |
| 固定方案最优 | 10,630,836 | 15,946,254 |
| 任意两批最优 | 6,215,339 | 7,565,637 |
| 降序两批 | 6,248,855 | 7,609,860 |
| 降序三批 | 5,983,957 | 7,071,460 |
| 降序四批 | 5,959,192 | 6,998,001 |
| 逐问最优 | 5,948,111 | 6,950,257 |

允许一次错读时，两批到三批少预订 231,382 字节，再加到四批只少 24,765 字节。此档案集合的实际最高返回载荷逐包相加，两批为 6,200,825 字节，三批为 5,953,219 字节。单文件等小目录会使多批与两批相同。次分析中，三批比精确两批少 6.53%，严格节省的包仍只有 5 个。没有用次分析替换原门槛。

独立程序从归档重建 223 条文件记录，核查 972 条回放计费，另用穷举切分端点的动态规划对照 6,675 个小规模最优值与比率不等式，并具体执行了 26,268 条答复历史。串行批排程已有降序或最早截止时间的先例。本次新增的是对诊断中分歧复查与末批全尾重读的费用刻画，以及它们合用时的比率证明。有限查新无法认定全球优先权。 [核验代码](weighted_rounds_check.py) · [核验输出](weighted-rounds-verification.json) · [逐项查新](weighted-rounds-prior.md)

## 复现

进入本文目录，使用 Python 3.10 或更新版本及 curl。脚本只解档读取，核验官方归档哈希与成员内容。

```sh
python -B weighted_rounds_bench.py npm-cache npm-results.json
python -B weighted_rounds_check.py npm-cache npm-results.json npm-verification.json
```
