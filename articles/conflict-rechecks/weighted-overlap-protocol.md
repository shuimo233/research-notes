# 多文件差异的独立发布历史留出

前面的异价复查中，每个旧解释只在一项探针上与目标发行不同。这里把旧解释换成真实较早发行的完整候选源码快照。对从 PyPI 获得的下列固定版本构造同一路径的内容比较，不运行包代码。协议先于本批档案下载、试验及文件报价读取完成。 [PyPI JSON API](https://docs.pypi.org/api/json/) · [单差异先前结果](weighted-batches.md)

| 包 | 四个旧候选，最后一列为新解释 |
| --- | --- |
| filelock | 3.15.4、3.16.1、3.17.0、3.18.0、3.19.1 |
| platformdirs | 4.2.2、4.3.2、4.3.6、4.3.7、4.3.8 |
| starlette | 0.40.0、0.41.3、0.42.0、0.44.0、0.46.2 |
| fastapi | 0.112.0、0.113.0、0.114.2、0.115.0、0.115.12 |
| anyio | 4.5.0、4.6.2.post1、4.7.0、4.8.0、4.9.0 |
| jsonschema | 4.20.0、4.21.1、4.22.0、4.23.0、4.24.0 |
| networkx | 3.1、3.2.1、3.3、3.4.1、3.4.2 |
| Babel | 2.13.1、2.14.0、2.15.0、2.16.0、2.17.0 |

仅保留五个 wheel 都存在、非空、属于包本身的普通 .py 路径，至少一版与新候选内容有差异。排除路径任一段为 tests、test、testing、docs、benchmarks、examples 的成员，大小写无关。每次预订按这一路径五版中最大未压缩字节计价。各档案按发布 SHA-256 校验，文件回复以 SHA-256 是否等于新版本为准。文件名、目录结构和分发元数据在当前接口不是可读探针。另做一个元数据可用的对照，把 .dist-info/METADATA 作为一个按最大尺寸计价的新检查。该对照用于评估便宜元数据是否已经足够。零可分性、缺版本、归档异常及空目录均报告，不替换包或挑掉旧候选。重复读取不代表可修复持久错误，本研究只允许瞬时单次报告被翻转。

主分析目标版本最多出错一次，旧版本在本阶段无剩余故障额度。次分析目标可错两次。错读是软件注入。对照包括最优固定覆盖、最优逐次选问，以及要求首批已覆盖所有旧差异的最优两批方案。主方法允许第一批之后仍有完全匹配的旧候选，由条件确认决定第二批。每种方案使用同一文件、成本和有界错误模型，普通与元数据对照分别报告。重放真实的五个版本内容及预设单次答复翻转，记录各包最坏预订、实际载荷、成本上界和不可判定条件。理论验证另以完整答复树穷举小例。

主任务预定效用判据是至少五个包在同回复掩码取最低价后仍含一个旧候选有两个或以上的差异检查，所有可分任务在重放中零误判，允许一次错读时两批总预订相对精确固定至少省 10%，且至少三个包比允许最优续问的全覆盖首批方案严格省费。若只有重复读取相比固定有利，将按该限制报告。除字节和轮数外无真实延迟或事故率指标。按真实发布的完整旧候选重放可检验文件结构和工作机制，但不能据此估计仓库、缓存或来源不完整时的风险。
