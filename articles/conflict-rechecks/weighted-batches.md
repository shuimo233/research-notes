# 复查费用不同时，只允许一次反馈要多付多少？

后续研究给出了降价连续三批的紧界，并在另十组 npm 档案上检验多一轮反馈的收益。 [三批实验](weighted-rounds.md)

当历史矛盾可能来自旧规则下的一次错读，也可能意味着需要新增规则，等成本下两批查询就能达到逐次反馈的最优最坏成本。异价时会出现差距。三项复查的价格是 9、3、3，逐问最坏需要 18，两批需要 21，固定名单需要 30。这个例子里每条旧解释只在一项测试上与新增解释不同。 [等成本结果](README.md) · [本轮证明](weighted-batches-proof.md)

在这个条件下，设旧解释已用尽故障额度，新增解释还可容许 $f$ 次读错。**两批相对于逐问的最坏成本比，其紧上界为 $1+(f/(f+1))^2$**。允许一次错读时是 $5/4$。若第一批只能取价格从高到低的前缀，紧上界变为 $1+f/(f+2)$，一次错读时为 $4/3$。两种上界都可以用整数价格任意逼近。程序可以直接按排序与预算装入构造有保证的名单。精确求最便宜的两批则弱 NP 完全，现有实现将位集截断到最大单价。 [证明、紧族与复杂度归约](weighted-batches-proof.md) · [调度器](weighted_batches.py)

## 这个区分怎样用于推理器

数字 $f$ 来自合同与已经收到的历史。每次复查后，推理器保留所有能解释当前回复的候选。第一批全与新增解释相符时，第二批集中核对还没碰到的旧解释。第一批只在某一项上发生冲突时，第二批集中复核该项。诊断接口会先检查有没有旧解释仍有错误余量，以及它们与新增解释是否真只在单一探针上不同。合同不允许归因时会返回歧义或不一致，并附回已有的候选与读数。预算不足时可以在预订前直接返回成本。 [可调用接口](weighted_diagnose.py)

这是一项条件化保证。若重复查询读取的是同一份已经损坏的持久记录，重复次数不能充当新的容错额度。若一个旧解释在多个探针上都不同，应另用能支持该差异结构的规划器。候选解释来自调用者，接口会检验它们的区分结构。

## 用发布档案回放

按事前预案取得 10 组公开 PyPI wheel、校验发布哈希，保留同路径且内容变化的 224 个 Python 文件。每个旧解释由一份真实旧版文件和其余新版文件构成。每次探针从档案重新读内容，由验收端计算 SHA-256，比对预期文件。取两个版本中较大的未压缩字节数作为固定预订价。真实档案提供文件内容和大小，替换与单次答复翻转由程序控制。 [冻结预案](weighted-batches-protocol.md) · [逐文件与逐包数据](weighted-batches-results.json)

允许一次错读时，十组发布包都通过了事先规定的 15% 节省门槛。保证构造相对固定方案汇总少预订 42.37%，实跑时各包最高实际返回载荷之和也从 9,475,280 字节降到 5,431,354 字节。精确两批少预订 45.75%，相对很强的降序前缀只额外少 0.72%，聚合预订成本比逐问高 7.13%。现有接口默认分别构造保证名单和最佳前缀，采用两者中预订较便宜的一份。需要最小价时可启用精确模式。这里的结果没有转换成网络时延、磁盘吞吐或云端账单。

独立核验直接从完整回复串反推存活解释，核对 627 个费用与容错配置、8,998 条显式执行历史、800 个更宽随机数值例和 35 个紧族算例。在 10 个实际归档复算所有入选成员的哈希和价格，并核对 976 条回放计数及相应最坏见证。已有 SQLite 归因通过同一接口运行了 9 条真实查询轨迹，并核验了预算不足及适用条件失败时的行为。 [独立核验](weighted_batches_check.py) · [核验记录](weighted-batches-verification.json)

## 先例与复现

带错查询、序贯诊断、异价批量测试都已有先例。把逐问分支化成按交付尾长排序也沿用已有排程问题。查新聚焦于这一非对称单差异合同下两批的精确值、紧比率和复杂度。当前查到的最接近工作没有给出同一结果。证据限于已经逐项核对的公开材料。 [逐条查新](weighted-batches-prior.md)

用 Python 3.10 或更高版本运行。档案数据下载需要 curl。下载器只取 wheel 字节做校验并解档读取，从包中不导入模块。进入本文所在目录。

```powershell
python -B weighted_bench.py wheel-cache weighted-batches-results.local.json
python -B weighted_batches_check.py wheel-cache weighted-batches-results.local.json weighted-batches-verification.local.json
```

核心求解和归因接口使用 Python 标准库。若已把每项观测归一化成相对于新增解释的 0 或 1，可直接把批回调传给 `execute`。若持有历史读数与两类预测函数，则使用 `attribute_with_prices`，回调接收真实探针名称并返回同序答复。 [接口与完整输入约定](weighted_diagnose.py)
