# 检验范围

运行结果生成前确定以下检验口径。每次复查从相同初态返回一比特，成本为 1。旧规则逐问如实回答，新增规则各自可在后续至多错答 f 次。一个动作可在多种规则下正确。正面命题要求所有新增规则共享至少一个可执行动作。

1. 在两个二元探针的四个签名中选两个旧和两个新。每个机制在两个动作上取任一非空允许子集，保留新增有公共动作的全部实例。分别取 f=0,1,2。精确求安全行动深度，并与独立枚举的整数多覆盖下界 L、以及 L 加旧签名辨识深度 D 比较。列出所有失配与取等情况。
2. 检验一个可放大的构造。旧模型有 d 个身份位及三个全零诊断位。新增模型复制身份位，三个诊断位中恰有两个 1。旧模型要求与身份对应的动作，新增模型共同要求另一动作。预测精确成本为 d+ceil(3(f+1)/2)。核验 d=0,1,2 与 f=0,1,2。
3. 去掉新增规则的公共动作。用一个接受两种动作的旧模型与两个要求相反动作的新模型，检验上界在 f>0 时是否失效。
4. 在 SQLite 主键冲突实验中，候选动作是普通插入整批、补齐尾部、恢复表头。每种动作的允许范围以实际执行成功且最终表精确等于目标为准。比较选择有效动作与查清策略的最优最坏复查次数，f=0,1,2。旧方 ROLLBACK/REPLACE，新增方 ABORT/FAIL/IGNORE。历史读数来自“键1存在、键1为新值”两项，旧方各注入一次错读使之与新增方共享历史。

以上是构造性验证，没有随机抽样、外部预注册或对自然任务发生率的估计。数学主张须有独立证明。
