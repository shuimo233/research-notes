# 修好数据库，需要先知道它为什么错了吗？

2026-11-21 · 可复现研究笔记

在一次 SQLite 主键冲突后，我们依次查到“键 1 存在”和“键 3 缺席”。即使容许接下来的复查中有一次读错，在这条记录上仍有三个解释能成立：SQLite 采用了 ABORT、FAIL 或 IGNORE。此时已经可以执行同一条修复语句，补齐键 2 和键 3 并保留已有行。我们在三个独立的内存数据库中分别执行了它，三张最终表逐行相同。

这提示我们更换评估指标。在这个例子里，要求系统查清五种策略中的哪一种，最坏需要 **5 次**复查。只要求选中一个确实能修好表的动作，最优最坏成本是 **3 次**。两者用相同的候选、初始历史、错误预算和四个允许的读数。

“原因尚未确定也能行动”早有正式定义。我们进一步问了一个有限成本问题：**多个新解释都容许错读时，怎样用可计算的上下界，估计一次正确行动还值多少次复查？** 下文给出证明、能取到上界的实例，以及去掉一个前提就失败的反例。

## 单次运行究竟保证什么

假设真实机制在一张有限表中。每个机制都对每个允许的实验给出确定的二元预测，也列出在该机制下可用的动作。动作正确与否由任务的外部验收条件决定。实验从同一状态重置，每次只返回一比特，费用相同。下面只算既有历史之后的复查次数。

- 旧机制已经用尽历史允许的错误额度。若它为真，后续每次读数都准确。
- 每个新增机制仍可有至多 $f$ 次读数偏离预测，位置由对手选择。所有新增机制至少共享一个可用动作，记为回退动作。
- 若几个旧机制在所有允许实验上都给出相同读数，把它们合成一个旧签名 $C$。给这个签名选动作时，须对组内每一个机制都有效。以下讨论至少有一个旧签名和一个新增机制。

“旧”和“新”描述的是当前证据留下的**剩余额度**，并不表示老系统的传感器天然更可靠。若所有尚存机制共用一个动作，复查成本直接是零。

## 能省到哪里，又至少要花多少

沿着某个旧签名 $C$ 始终如实回答的路径考虑。打算执行动作 $a$ 时，只需排除那些**不允许 $a$** 的新增机制。要排除其中一个 $e$，必须在 $C$ 与 $e$ 预测不同的实验上累计至少 $f+1$ 次读数。少一次，$e$ 仍可用自身的错读额度解释整条路径。

记 $L_C$ 为以下两个选择达到的最低总次数：选一个对签名 $C$ 有效的动作，再选一份可重复的实验清单，把每个不允许该动作的新增机制都覆盖至少 $f+1$ 次。取 $L=\max_C L_C$。再记 $D$ 为只在准确的旧签名之间辨认身份所需的最优最坏次数。则保证选对动作的最优最坏成本 $T$ 满足

$$
L \le T \le L+D.
$$

**下界。** 任何策略在真实机制属于 $C$ 时都有一条确定回答路径。停止时执行的动作必须对 $C$ 有效，且路径上的实验必须满足上述次数要求，否则同一条记录还可能来自一个不允许该动作的新增机制。这对每个 $C$ 都成立。

**上界。** 先用至多 $D$ 次查清哪一个旧签名还可能成立。若所有旧签名都被排除，立即执行公共回退动作。若只剩 $C$，再做其最省的动作验证清单。只要有一次读数与 $C$ 不符，所有旧机制就都被排除，可以回退。若全部符合，清单已排除所有会使选定动作错误的新增机制。两阶段可能使用同一证据，上界允许重复计费。

如果 $C$ 与某个新增机制的读数完全一样，选择动作时须同时满足它们；若组内旧机制和所有这些不可区分的新增机制没有共同动作，则不存在保证成功的有限策略。两两有共同动作仍然不够，必须核对整组的交集。

**固定安排和两批安排。** 记 $S$ 为一份预先排定的、能分开所有旧签名的最短实验清单长度。固定方案要给所有 $C$ 共用一份实验清单，但允许不同 $C$ 最终选不同动作。记满足每个 $C$ 的上述覆盖要求的最短公共清单长度为 $L_{\rm fix}$，则

$$
L_{\rm fix}\le T_{\rm fix}\le L_{\rm fix}+S,\qquad
L\le T_{\rm two\ batches}\le L+S.
$$

固定下界来自每个旧签名都必须能沿同一份清单安全交付；提前停止的方案可以补齐到完整清单。上界只需把用来分开旧签名的清单拼到公共清单前。若允许一次批间反馈，第一批分开旧签名后，第二批就可换成该签名自己的清单。$D$ 与 $S$ 可能不同。

**错误额度变大时。** 在计算 $L_C$ 的覆盖问题中，把每个实验的执行次数放宽为非负实数，把每个需排除的机制覆盖一次即可。对每个动作求这个分数覆盖的最小总量，仍然先选 $C$ 可用动作中的最小值，再取各 $C$ 的最大值，记作 $\lambda$。在可行实例上，

$$
(f+1)\lambda \le T \le (f+1)\lambda+|Q|+D,
$$

其中 $|Q|$ 是可用实验种数。证明只用到两步：整数计划除以 $f+1$ 即为分数可行解；反过来，把分数最优解乘以 $f+1$，再逐项向上取整，增加的总量至多 $|Q|$。所以 $T/(f+1)$ 趋于 $\lambda$。把 $D$ 换为 $S$，两批方案也达到同一极限。这里给出的有限加性余量限定了统计研究中相似的分数配置量，在本模型中究竟能说明多少。

## 三个能把结论推翻的检验

**一、加上的 $D$ 能全部花掉。** 设旧机制有 $d$ 个身份位，另有三个读数总是 0。每种旧身份只允许自己的修复动作。新增机制复制任一身份，但三个诊断位恰有两个为 1，共用同一个回退动作。对真实旧机制，少读一个身份位，就无法分开另一个需要不同修复的旧机制。只读身份位也无法排除复制同一身份的新增机制。

令 $r=f+1$。三个诊断位的复查次数为 $x,y,z$，必须满足 $x+y,x+z,y+z\ge r$。相加得总次数至少 $\lceil3r/2\rceil$；取三个尽量均衡的整数即可达到。因此精确最坏成本是 $d+\lceil3(f+1)/2\rceil$。非整数的一阶系数 $3/2$ 和完整的身份成本 $D=d$ 可以在同一个实例中出现。

**二、公共回退动作不可随意删除。** 一个旧机制预测 10，允许动作 A 和 B；两个新增机制分别预测 00 与 01，各自只允许 A 或 B。旧签名的局部下界是 $f+1$，旧签名辨识成本为零。但区分两个新增机制可能需要 $2f+1$ 次。重复查询第二位可达此数；对任意更短的策略，在第二位上交替答 0、1，第一位始终答 0，两个新增机制都能解释至多 $2f$ 次的记录。$f=2$ 时，两种成本实为 3 和 5。

**三、接口不变，固定计划也可能昂贵。** 作为追加分析，给 $k$ 个旧签名各配一个相异地址和一个专属标记位；旧签名 $i$ 只有标记 $i$ 为 1。每个新增机制复制一个地址，但所有标记均为 0。旧方各需相应修复，新增方可统一回退。固定清单必须把每个标记检查 $f+1$ 次，因为每对同地址的新旧机制只在那个位置不同；这 $k(f+1)$ 次也足够。两批方案第一批读地址，第二批只重查对应标记，至多花 $\lceil\log_2 k\rceil+f+1$ 次（未使用的地址可直接回退）。另有 $f+1$ 次的单对下界，因此在固定 $k$、增大 $f$ 时，固定与两批的成本之比趋于 $k$。例如 $k=4,f=2$，程序搜索得逐问最优 5 次，两批也用 5 次，固定最优 12 次。这是说明一般界的构造；固定和反馈查询相差很大，在已有容错探测研究中也有先例。

## SQLite 的动作是否真能执行

每次复查都开启一个新的内存数据库事务：先写入键 1 的旧值，再在一条语句中尝试写入键 2、键 1 的新值、键 3，中间触发主键冲突。数据库按实际冲突策略处理。测试程序在**读数返回后**注入错误。共同历史为“键 1 存在、键 1 还不是新值”。ROLLBACK 和 REPLACE 都需要恰好一次历史错读，另外三种策略无需错读。复查只能问四个布尔问题：三个键是否存在、键 1 是否为新值。[SQLite 冲突处理规范](https://www.sqlite.org/lang_conflict.html)

验收目标是表中恰有三行，值分别为 old、prefix、suffix。三个允许动作是普通插入整批、保留已有行并补齐尾部、恢复键 1 的旧值。我们在五种数据库策略下逐一执行全部 15 个组合，以 SQL 执行成功且最终表完全一致界定动作是否有效。

| 数据库冲突策略 | 实测有效的动作 |
| --- | --- |
| ROLLBACK | 插入整批 |
| REPLACE | 恢复键 1 |
| ABORT、FAIL | 补齐尾部 |
| IGNORE | 补齐尾部，或恢复键 1 |

| 新增方可再错读 | 保证动作正确 | 保证查清具体策略 |
| ---: | ---: | ---: |
| 0 次 | 2 次 | 3 次 |
| 1 次 | 3 次 | 5 次 |
| 2 次 | 4 次 | 8 次 |

表内均为最优最坏复查次数，不含两次共同历史和最后执行的修复。每种额度都枚举了最优行动策略下每个真实机制的可达读数分支，并在全新同状态数据库执行最终动作。三档合计 35 个“真实机制 × 停止记录”均通过最终表核验。证据文件的 sqlite_action_rows 还保存了全部 15 个策略与动作组合的最终行，null 表示动作触发完整性错误。把一次错读档的最优深度故意少写 1，或把“恢复键 1”标成能修复 ABORT，两个对应检查均拒绝。公开的三种动作是这个实验的约束；若允许直接覆盖整张表，问题会改变。

**在这张具体的数据库表上，行动列对任意 $f$ 都恰好是 $f+2$。** 设 $r=f+1$。ROLLBACK 只能选“插入整批”，而 ABORT 不能；两种策略仅在“键 1 存在”上读数不同。所以在真实 ROLLBACK 路径上必须查这项至少 $r$ 次。若想在总共 $r$ 次内保证完成，第一问就必须是这一项。可是在真实 REPLACE 路径上，第一问的答案与 FAIL 相同；REPLACE 唯一允许的“恢复键 1”在 FAIL 下会缺一行。余下最多 $r-1$ 问，无论怎样选都排不掉 FAIL。这证明 $r$ 次不够。上界可以直接做到：第一问用键 1 区分两个旧签名，再按该签名至多复测 $r$ 次键 1 或“键 1 为新值”。这是针对特定 SQL 流程、读数库和动作验收条件的完整结论。

## 复现与可主张的范围

在两个二元探针、四个不同签名、两个旧机制和两个新增机制的完整小表上，枚举两种动作的所有非空允许集合，保留新增方有公共动作的情形。每档 $f$ 有 378 个实例，三档合计 1,134 个。逐问界均通过。对每档的 326 个实例，最优成本等于 $L$；另 52 个恰等于 $L+D$，这里 $D=1$。固定设计和逐问设计在 $f=1,2$ 时各只有 8 个实例呈严格差距。这个数描述指定的小表空间，不能估计真实业务的收益率。

第一份程序按每个候选的剩余错误额度搜索决策树，并独立枚举整数多覆盖。第二份程序从头实现了另一种检查：把某个深度内可能错读的时刻展开成确定的回答序列，分别验证所报深度是否可行以及少一步是否仍可行。两个检查器复得小表统计和 SQLite 的六项最优深度。第二份程序还检验行动交集为空的不可判别例子。这里的独立指实现方式，两份代码均来自本项目。[实验口径](PROTOCOL.md) · [第一份程序](verify.py) · [独立实现](audit.py) · [实验数据](evidence.json) · [追加复核数据](audit-evidence.json)

在本目录用 Python 3.10 或更高版本运行以下命令，两份 JSON 输出分别对应上面的数据文件。

~~~shell
python -I -B verify.py
python -I -B audit.py
~~~

这项工作支持的是一个有限推理模块：给定明确的机制、动作验收条件与错读上限，可以计算行动所需的证据，检查反馈是否值得，并在条件不足时报出反例。生成正确的新机制、从真实日志可靠地估计错误上界、把同样保证带入开放环境，仍是三个待解决的问题。
